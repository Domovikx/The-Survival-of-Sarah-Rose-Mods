# Имена файлов озвучки: `{en16}__{state8}__{variant}.opus`

Черновик решения (2026-11-16). Проблема: имя opus-файла содержало только
`uid = md5(английский оригинал)`, поэтому при правке **перевода** нельзя было
понять, устарел ли звук — файл на месте, а внутри озвучена старая фраза.

## Схема имени

```text
{en16}__{state8}__{variant}.opus
   │        │         └── имя голоса как есть: Narrator, Sarah, Sarah_1
   │        └──────────── md5(канонический JSON {emotion,text})[:8]  «что произносится»
   └───────────────────── md5(EN-оригинал)[:16]                      «какая это реплика»
```

Пример: `007b60073b571d0a__b706ca10b738a4b8__Narrator.opus` (41 — 46 символов).

## Что именно хэшируется в state8

Хэшируется **канонический JSON** аудио-идентичности:

```json
{"emotion":"Mocking and detached","text":"Ты можешь делать это для них — они к тебе правильно отнесутся."}
→ md5 ecfe02c47617ad0a556700189b32f2ca → state8 ecfe02c4
```

Канон (без него одинаковые данные дают разные хэши):

- ключи по алфавиту, без пробелов, без `\u`-эскейпов (UTF-8 как есть);
- оба поля присутствуют всегда (`emotion: ""` когда тона нет), `null` не используется;
- `text` — результат `ttsText()`: NFC, без `{тегов}` и `[переменных]`, без лишних
  пробелов, без осиротевшей пунктуации в начале.

**Поля ровно два — `emotion` и `text`.** Это зафиксировано тестом: новый
по-репличный вход, влияющий на звук, обязан появиться в JSON, иначе файл будет
считаться актуальным при другом звуке (тест красный).

Версии схемы (`"v":1`, `"schema":"…"`) **нет сознательно**: JSON никто не видит
(в имя попадают 8 символов хэша), а любое изменение набора полей и так меняет
хэш. Лишнее понятие, которое пришлось бы помнить.

Порядок выбран так: спереди два **фиксированных** хэша (разбор однозначен), а
человекочитаемый голос — в хвосте, где он был и раньше (`…__Sarah.opus`).

## Почему такие длины (проверено на реальных данных)

**EN = 16 hex (64 бита).** Коллизия здесь = чужой файл молча затёрт / играет не та
реплика. На 68 113 уникальных текстах игры:

| префикс | бит | реальных коллизий | ожидаемо  |
| ------- | --- | ----------------- | --------- |
| 8 hex   | 32  | **1**             | 0.54      |
| 10 hex  | 40  | 0                 | 0.002     |
| 12 hex  | 48  | 0                 | 8·10⁻⁶    |
| 16 hex  | 64  | 0                 | 1.3·10⁻¹⁰ |

16 — ещё и бесплатно: это первая половина текущего 32-hex uid, пересчитывать
ничего не нужно.

**state = 8 hex (32 бита).** Коллизия здесь = «поверили, что файл актуален,
хотя текст другой». Проверено на реальной истории правок (`git log` по
`ru/zh/es`, **63 877 правок**):

| state | промахов на 63 877 правок | ожидаемо за проект (~900 тыс.) |
| ----- | ------------------------- | ------------------------------ |
| 3 hex | 13 (0.020 %)              | ~219                           |
| 4 hex | 1 (0.002 %)               | ~14                            |
| 5 hex | 0                         | ~0.9                           |
| 6 hex | 0                         | ~0.05                          |
| 8 hex | 0                         | **~0.0002**                    |
| 16    | 0                         | ≈ 0                            |

Лавинный эффект полный: правка **на один символ** меняет ~30 из 32 hex-символов
(64 из 128 бит), включая все первые. Поэтому «запоминать первые 5» бессмысленно —
либо 5 символов и ~1 промах на 100 тыс. правок, либо 8 и промах раз в 5000 проектов.

Важно: короткий `state` безопасен **только потому, что имя начинается с `en16`**.
Без привязки к реплике (если искать только по state) на 5 символах 26 139 из
238 803 реальных переводов совпали бы с чужой строкой.

## Как это работает end-to-end

```text
        template.pot (EN, arc, emotion, категория)
                    │
   po/<lang>.po ────┴──► TTS_TEXT(lang, строка)      перевод (для en — оригинал)
                              │
                              ├─ sanitizeForTts(): убрать {теги}, решить про [переменные]
                              │
        en16 = md5(EN)[:16] ──┼── state8 = md5(JSON {emotion,text})[:8]
                              │
                              ▼
        audio/<lang>/<arc>/{en16}__{state8}__{variant}.opus
                              │
        ┌─────────────────────┼──────────────────────┐
        │                     │                      │
   voice_batch           voice_stale            voice_config.rpy (игра)
   файл есть → skip      список устаревших      uid16 = md5(EN)[:16]
   нет → синтез          удаление старых        glob uid16 + "*" → файл
```

### Генерация (`voice_batch`)

1. Для каждой строки POT категории dialogue/narration и каждого языка:
   `text = sanitizeForTts(перевод)`; пустой перевод → пропуск (озвучивать нечего).
2. `name = {en16}__{state8}__{variant}.opus`.
3. Файл с таким именем существует → **пропуск** (перегенерация не нужна).
   Нет → синтез.
4. `--force` — когда менялся движок/параметры/реф голоса (см. ниже).

### Проверка устаревшего (`voice_stale`)

Для каждого файла в `audio/`:

| что нашли                                     | класс           | что делать                                         |
| --------------------------------------------- | --------------- | -------------------------------------------------- |
| имя не разбирается (легаси `{32}__{variant}`) | `LEGACY`        | переименовать при миграции, иначе перегенерировать |
| `en16` нет в POT                              | `ORPHAN`        | строки больше нет — удалить файл                   |
| `state8` ≠ ожидаемого по текущему po          | `STALE`         | перегенерировать, затем удалить старый             |
| `variant` нет в кастах/`voice_list.json`      | `UNKNOWN_VOICE` | разобраться с рефом, потом решать                  |
| всё совпало                                   | `OK`            | ничего                                             |

Отчёт: `--list` (по умолчанию), `--delete` (после подтверждения), `--verify`
(сверка с POT и с историей po для случая «файл сделан до правки»).

### Рантайм (`voice_config.rpy`)

```python
uid = hashlib.md5(_last_say_what.encode("utf-8")).hexdigest()[:16]
# 1) точное имя по варианту голоса из voice_list.json
# 2) фолбэк: glob uid + "*" (первый по алфавиту)
```

Рантайм **не знает** `state8` (тон и перевод в POT ему не видны), поэтому работает
по префиксу. Это нормально: после генерации у реплики ровно один файл — старые
удаляет `voice_stale`. Исключение — 13 строк, повторяющихся с разным тоном: у них
по два файла, играет первый по алфавиту (текст верный, тон может быть «соседний»).

### Что меняется — что происходит

| событие                                           | имя файла           | что делает пайплайн                                                               |
| ------------------------------------------------- | ------------------- | --------------------------------------------------------------------------------- |
| новая строка в POT                                | новое `en16`        | генерируется                                                                      |
| правка перевода                                   | новый `state8`      | старый → `STALE`, генерируется новый                                              |
| правка тона (`#. emotion:`)                       | новый `state8`      | то же                                                                             |
| правка английского оригинала                      | новый `en16`        | это уже другая реплика: новый файл, старый → `ORPHAN`                             |
| заменили реф голоса `Sarah.wav`                   | **имя не меняется** | нужен манифест `catalog/voice_state.json` (хэш рефа) → `--force` для этого голоса |
| сменили движок/параметры                          | имя не меняется     | `params_version` в манифесте → `--force`                                          |
| включили/сменили голос у спикера (null → `Sarah`) | имя не меняется     | прогон этого персонажа (`--char`)                                                 |

## Что ещё обязательно (найдено при проверке корпуса)

1. **`sanitizeForTts()`** — единая функция, и хэшируется её **выход**. Сейчас
   очистки нет: 6 реальных реплик содержат `{i}…{/i}` и `[unifyarmies]`
   (подстановка числа!) — TTS произнесёт токены буквально. Политику для
   `[…]` (вырезать или не озвучивать строку) надо решить до первой генерации.
2. **Манифест `catalog/voice_state.json`** — версия движка/параметров и хэш рефа
   каждого варианта. Без этого «файл есть» не значит «голос тот».
3. **NFC-нормализация** текста перед хэшем (вставки с macOS дают NFD —
   визуально одинаковый текст давал бы разные имена).
4. **Удаление stale сразу после генерации** — иначе в окне между генерацией и
   чисткой glob может сыграть старый файл.
5. **Легаси-имена** (`{32}__{variant}.opus`) считаются `LEGACY` — их находит
   миграция; рантайм после миграции их не увидит (другой префикс).

## Миграция существующего корпуса (13 347 файлов, 230 МБ, всё в git)

### Результат миграции (2026-11-16)

|                 |                                                                                                    |
| --------------- | -------------------------------------------------------------------------------------------------- |
| переименовано   | **13 069** файлов за 21 с (только метаданные, без перекодирования)                                 |
| коллизий        | 0                                                                                                  |
| осталось легаси | **278** (по 30–31 на язык, все вне ru/en): перевода на момент генерации в `po` не было             |
| аудит после     | ru 1397 OK, en 1195 OK, остальные OK кроме **zh: 2 STALE** (канон названия игры, фраза про Мэрион) |

Контракт рантайма проверен на 509 файлах (ru/zh/en): `md5(EN)[:16]` находит файл,
ровно как это делает `voice_config.rpy`. Легаси-имена тоже находятся — по фолбэку
`{uid16}*`.

1. `en16` = первые 16 символов текущего uid (пересчёт не нужен).
2. `state8` = `md5(канонический JSON {"emotion":<тон>,"text":<перевод>})[:8]`.
   Версию перевода берём из git: последний коммит `po/<lang>.po` **до mtime файла**
   (проверено, работает). Так имя остаётся честным: «файл сделан из ТОГО текста».
3. Сразу после — `voice_stale --list`: он и покажет реальный объём переозвучки.
   На момент проверки (2026-11-16) устаревших **2 файла** (оба `zh`: канон
   названия игры и фраза про Мэрион).
4. Переименование — только метаданные: замерено **~3.6 с на 13 347 файлов**,
   без перекодирования и без синтеза.
5. Отдельный класс: 24–31 файл на язык, у которых перевод в po сейчас **пуст**
   (озвучивать нечего) — их либо перегенерировать после перевода, либо удалить.

## Альтернатива, от которой отказались

**Манифест вместо имени** (имя `{uid}__{variant}.opus`, состояние в JSON): имя
короткое навсегда, но индекс надо держать в синхроне, копирование отдельных файлов
теряет состояние, а без индекса «устарел ли» не определить. Имя с двумя хэшами
самодостаточно, чистка — глоб по префиксу. Манифест остаётся **только** для того,
чего в имени нет: рефы и версия движка.
