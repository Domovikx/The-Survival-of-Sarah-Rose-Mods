# Имена файлов озвучки: `{en12}-{state6} {variant}.opus`

Решение (2026-11-16, финальный формат 2026-11-17). Проблема: имя opus-файла
содержало только `uid = md5(английский оригинал)`, поэтому при правке **перевода**
нельзя было понять, устарел ли звук — файл на месте, а внутри озвучена старая фраза.

## Схема имени

```text
{en12}-{state6} {variant}.opus
   │       │      └── имя голоса как есть: Narrator, Sarah, Sarah_1, King Orwell Rose
   │       └───────── base32(md5(канонический JSON {emotion,text})[:4])[:6]  «что произносится», 30 бит
   └───────────────── base32(md5(EN-оригинал)[:8])[:12]                      «какая это реплика», 60 бит
```

Пример: `IBFHGIFFGB4R-V6A4KO King Orwell Rose.opus` (41 символ, максимум 65).

Алфавит — **base32 RFC4648** (`A-Z2-7`, только верхний регистр):

- регистронезависимо безопасно (Windows/macOS не различают `a` и `A`, а base64 — различает);
- нет символов, ломающих имена файлов и регулярки (`-`, `_`, пробел остались только
  как разделители);
- кодировщик родной и в Node (свой 15-строчный, см. `voice_names.mts`), и в Python
  (`base64.b32encode`) — паритет стережёт тест, который считает имя обоими путями.

Разделители: `-` между хэшами, пробел перед голосом. Голос стоит последним, поэтому
может содержать и пробелы, и дефисы — разбор всё равно однозначен (два
фиксированных хэша спереди).

## Что именно хэшируется в state6

Хэшируется **канонический JSON** аудио-идентичности:

```json
{"emotion":"Mocking and detached","text":"Ты можешь делать это для них — они к тебе правильно отнесутся."}
→ md5 ecfe02c47617ad0a556700189b32f2ca → base32(первые 4 байта) 5T7AFR
```

Канон (без него одинаковые данные дают разные хэши):

- ключи по алфавиту, без пробелов, без `\u`-эскейпов (UTF-8 как есть);
- оба поля присутствуют всегда (`emotion: ""` когда тона нет), `null` не используется;
- `text` — результат `ttsText()`: NFC, без `{тегов}` и `[переменных]`, без лишних
  пробелов, без осиротевшей пунктуации в начале.

**Поля ровно два — `emotion` и `text`.** Это зафиксировано тестом: новый
по-репличный вход, влияющий на звук, обязан появиться в JSON, иначе файл будет
считаться актуальным при другом звуке (тест красный).

Версии схемы (`"v":1`, `"schema":"…"`) **нет сознательно**: JSON никто не видит
(в имя попадают 6 символов), а любое изменение набора полей и так меняет хэш.

## Почему такие длины (проверено на реальных данных)

**`en12` = 60 бит.** Коллизия здесь = два разных текста получили одно имя
(невидимая ошибка: играет не та реплика). На корпусе игры (67 365 уникальных
текстов, из них 1 919 микро-фраз ≤12 символов):

| вариант | бит | реальных коллизий | ожидаемо |
| ------- | --- | ----------------- | -------- |
| en6     | 30  | **2**             | 2.1      |
| en8     | 40  | 0                 | 0.002    |
| en12    | 60  | 0                 | 2·10⁻⁹   |

Ёмкость `en12`: 1.5 млн фраз при требовании «1 коллизия на миллион» (48 млн при
«1 на тысячу»). Пространство `en` **не накапливается между проектами** — у каждой
игры свой корпус. Микро-фразы отдельно проверены: 0 коллизий (риск зависит от
числа разных текстов, а не от их длины; md5 лавинный).

**`state6` = 30 бит.** Коллизия здесь = «поверили, что файл актуален, хотя текст
другой». Замер по истории репозитория — **64 972 реальных правки перевода**
(ru 62 231, остальные языки почти не правились, это пол):

| state  | бит | ожидаемо «молча устаревших»                   |
| ------ | --- | --------------------------------------------- |
| state4 | 20  | 0.062 (1 к 16) → с будущими вычитками 1 к 4–8 |
| state5 | 25  | 0.0019 (1 к 500)                              |
| state6 | 30  | 0.0001 (1 к 10 000)                           |

Тон меняется редко и оптом (в истории POT — два массовых overlay), риск идёт от
правок текста. Совпадение префикса при правке — лотерея `1/32^k`, размер правки
не влияет: проверено на 803 036 реальных правках — 0 совпадений на 4 символах,
6 на 3.

## Как это работает end-to-end

```text
        template.pot (EN, arc, emotion, категория)
                    │
   po/<lang>.po ────┴──► ttsText(lang, строка)       перевод (для en — оригинал)
                              │
        en12 = base32(md5(EN)[:8])[:12] ──┼── state6 = base32(md5(JSON)[:4])[:6]
                              ▼
        audio/<lang>/<arc>/{en12}-{state6} {variant}.opus
                              │
        ┌─────────────────────┼──────────────────────┐
        │                     │                      │
   voice_batch           voice_stale            voice_config.rpy (игра)
   файл есть → skip      список устаревших      en12 = base32(md5(EN)[:8])[:12]
   нет → синтез          удаление старых        glob `{en12}-* {variant}` → файл
```

### Генерация (`voice_batch`)

1. Для каждой строки POT категории dialogue/narration и каждого языка:
   `text = ttsText(перевод)`; пустой перевод → пропуск (озвучивать нечего).
2. `name = {en12}-{state6} {variant}.opus` (`voiceBase` в `voice_names.mts`).
3. Файл с таким именем существует → **пропуск** (перегенерация не нужна).
4. `--force` — когда менялся движок/параметры/реф голоса (см. ниже).

### Проверка устаревшего (`voice_stale`)

| что нашли                                   | класс           | что делать                             |
| ------------------------------------------- | --------------- | -------------------------------------- |
| имя предыдущей схемы `{en16}__{state8}__`   | `HEX`           | переименовать: `voice_migrate`         |
| имя самой старой схемы `{uid32}__{variant}` | `LEGACY`        | состояние неизвестно → переозвучить    |
| `en12` нет в POT                            | `ORPHAN`        | строки больше нет — удалить файл       |
| `state6` ≠ ожидаемого по текущему po        | `STALE`         | перегенерировать, затем удалить старый |
| `variant` нет в кастах/`voice_list.json`    | `UNKNOWN-VOICE` | разобраться с рефом                    |
| всё совпало                                 | `OK`            | ничего                                 |

`HEX` отделён от `LEGACY` намеренно: у них разные лекарства (переименовать против
переозвучить), и смешать их значило бы дать `--delete-legacy` возможность снести
весь корпус во время миграции.

### Рантайм (`voice_config.rpy`)

```python
uid = base64.b32encode(hashlib.md5(text.encode("utf-8")).digest()[:8]).decode()[:12]
# 1) glob `{uid}-* {variant}.{opus,wav}`  — вариант голоса из voice_list.json
# 2) фолбэк: glob `{uid}-*.{opus,wav}`    — любой файл этой реплики
# из найденных берётся САМЫЙ СВЕЖИЙ по mtime (устаревшее состояние рядом с текущим)
```

Рантайм **не знает** `state6` (тон и перевод в POT ему не видны), поэтому работает
по префиксу. Пока старые файлы не удалены, у реплики может быть два состояния —
поэтому выбирается последний по mtime: его записала последняя генерация. Чистка
(`voice_stale --delete`) оставляет ровно один файл.

### Что меняется — что происходит

| событие                          | имя файла           | что делает пайплайн                                  |
| -------------------------------- | ------------------- | ---------------------------------------------------- |
| новая строка в POT               | новое `en12`        | генерируется                                         |
| правка перевода                  | новый `state6`      | старый → `STALE`, генерируется новый                 |
| правка тона (`#. emotion:`)      | новый `state6`      | то же                                                |
| правка английского оригинала     | новое `en12`        | другая реплика: старый → `ORPHAN`                    |
| заменили реф голоса `Sarah.wav`  | **имя не меняется** | нужен манифест `catalog/voice_state.json` (хэш рефа) |
| сменили движок/параметры         | имя не меняется     | `params_version` в манифесте → `--force`             |
| включили/сменили голос у спикера | имя не меняется     | прогон этого персонажа (`--char`)                    |

## Миграция корпуса (2026-11-17)

Все 13 347 файлов в git, поэтому переименование — только метаданные.

|                             |                                                                 |
| --------------------------- | --------------------------------------------------------------- |
| переименовано               | **13 131** файл в base32-схему                                  |
| удалено мёртвых             | **119** (имени не построить: перевода нет ни в одной версии po) |
| осталось легаси             | **97** (24 × de/es/pt/zh + 1 ja) — ждут переозвучки             |
| коллизий                    | 0                                                               |
| аудит после                 | ru 1397 OK, en 1195 OK; `STALE` — pt 1, zh 2                    |
| самый длинный путь в архиве | 98 символов (запас до буфера 240)                               |

Как считается текст при переименовании: берётся версия `po/<lang>.po` **на момент
mtime файла** (последний коммит до него) — так имя остаётся честным: «файл сделан
из ТОГО перевода». Если такой версии нет, но `state8` из старого имени совпадает с
текущим переводом, файл актуален и переименовывается по текущему тексту.

Не мигрируют и остаются `LEGACY` (`{uid32}__{variant}`): 97 файлов Prologue/
StoryBeginnings и др., озвученных из старого `tl/`-префилла — их текст неизвестен,
поэтому нужно переозвучить (`voice_batch --force --uid`), а не переименовывать.

## Чего имя не закрывает

**Манифест `catalog/voice_state.json`** — версия движка/параметров и sha1 рефов.
Имя отвечает на «та ли это реплика и тот ли текст», но не на «тем ли голосом и с
теми ли параметрами она синтезирована». До манифеста `--force` остаётся ручным.

## Альтернативы, от которых отказались

- **Манифест вместо имени** (`{uid}__{variant}.opus` + JSON-состояние): индекс надо
  держать в синхроне, копирование отдельных файлов теряет состояние, без индекса
  «устарел ли» не определить. Имя с двумя хэшами самодостаточно.
- **hex вместо base32**: на 6 символов длиннее при том же числе бит и требует двух
  разных алфавитов в документации и тестах.
- **base64**: регистр несёт информацию, а Windows/macOS регистронезависимы.
- **`__` вместо `-`+пробел**: −2 символа, но читается хуже (решение владельца
  2026-11-17: «визуально более красиво и читабабельно»).
- **`.` вместо `-`**: точка в середине имени читается как расширение и ломает
  `splitext`-логику.
- **`en13`**: +1 символ даёт ×5.6 ёмкости, но пространство `en` не накапливается
  между проектами — 1.5 млн фраз хватает с запасом.

## Гейты: кто имеет право писать в корпус

Правило одно: **`patches/ai-voice-pack/audio/` пишет только `voice_batch.mts`**
(он единственный строит имена через `voiceBase` → `{en12}-{state6} {variant}`).
Всё остальное — стенд, отбор, эксперименты — живёт вне корпуса.

- **Стенд `voxcpm_bench.mts`** по умолчанию пишет в
  `tools/generate/output/voxbench/<lang>/<arc>/`; если его нацелить внутрь
  `audio/` (`--out-dir`), он останавливается до генерации с объяснением
  (`corpusWriteError`).
- **`vox_qc.mts` / `vox_level.mts`** по умолчанию смотрят туда же — в папку стенда.
- **`countDone` / `catalog_gen.countAudio` / `healthScan.junk`** считают озвучкой
  только имена по контракту (`isCorpusName`): бенч-файл не «прогресс» и не
  «озвучено N» в меню мода.
- **`voice_role_audit`** классифицирует всё не по контракту как `WEIRD`
  (раньше легаси-схемы принимались за норму и мусор проходил как `OK`).
- **`build_pack`** падает (`ArchiveAbort`) на любом файле не по контракту —
  мусор физически не может уехать в релиз.
- **`voice_corpus.test.mts`** требует легаси = **0** (раньше допускал `<300` —
  именно этот допуск скрыл инцидент) и **запускается в CI** (`test:voice:corpus`).

## Инцидент 2026-11-20: 1 851 файл, которого не видит игра

- **Симптом:** ночной прогон EN «прошёл» 2 арки и 586/703 третьей, счётчики
  показывали 2 998 озвученных реплик, в `audio/en/` лежало 1 851 новый файл.
- **Причина:** `voice_ctl vox-start` запускал легаси-очередь `vox_queue.mts`,
  а она зовёт `voxcpm_bench.mts`; стенд не умеет контрактных имён (в нём нет ни
  `en12`, ни `state6`) и писал `{uid}__{voice}__Vox_cfg2.6_ts30_dn.opus` прямо
  в `audio/en/<arc>/`. Рантайм ищет `{en12}-* {variant}.opus` → файлы невидимы.
- **Почему не поймали раньше:** тест корпуса существовал, но (а) допускал
  до 300 легаси-файлов, (б) не запускался ни в CI, ни перед сборкой; счётчики
  (`countDone`) считали любой `.opus`.
- **Лечение:** `vox-start` = `voice_batch --engine voxcpm2 --lang <l>`;
  `vox_queue` отключён; гейты выше; мусор вынесен из корпуса и удалён
  (настройки бенча `cfg 2.6 / seed 49` отличались от канона `cfg 2.0 / seed 42`,
  поэтому переименование не спасало — звук был бы другим).
