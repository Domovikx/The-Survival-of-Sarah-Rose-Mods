# PIPELINE.md — памятка пайплайна TSSR-модов

Единая последовательность «как что идёт». **Актуализируй вместе с пайплайном**:
изменил шаг/команду — правь эту памятку в том же рабочем дереве.

## Источники истины (одна правда на каждый слой)

- **игра** (`game/*.rpy` в установке Steam) — апстрим, сырьё. НЕ истина:
  меняется каждым апдейтом игры, не содержит ни uid, ни спикеров, ни тона.
- **`patches/ai-voice-pack/po/`** — истина текста. `template.pot` пишет ТОЛЬКО
  potgen; `po/<lang>.po` — переводы (ru=msgstr, en=msgid). Языки-брони: ru, es.
- **`patches/ai-voice-pack/catalog/emotions.json`** — LLM-разметка тона
  (uid → emotion, ВСЕГДА EN) — ИСТОЧНИК `#. emotion:` в POT; привязка к фразе
  по uid = md5(msgid): пока текст не менялся, тон переживает обновление игры;
  фраза изменилась → новый uid → тон сброшен и навешивается заново ВРУЧНУЮ
  по семантике и эмоциональному контексту. Удалять запрещено (инцидент
  a16e21ef9: «легаси»-каталог вынесен → POT остался без тона;
  восстановлено из истории 2026-10-21, памятка — renpy-po/SKILL.md).
- **`patches/ai-voice-pack/casts/`** — истина голосов: касты (`{Name}.mts`-контракт
  с рефами) и типизированная мапа «спикер POT → голос» `casts.mts` (CAST_NAMES / SPEAKERS /
  LINE_OVERRIDES; ревью — тул speakers:audit).
- **`patches/ai-voice-pack/catalog/`** — производные джойны (не править руками).
- **`patches/ai-voice-pack/audio/`** — результат (uid__Who.opus), не БД.

## Последовательность шагов

### Шаг 1 — текст: игра → template.pot

- Команда: `npm run potgen`
- Что делает: обходит все `game/*.rpy` двумя проходами (все define Character →
  затем реплики), вытаскивает реплики и интерфейсные `_()`, дедуплицирует,
  пишет ПОЛНУЮ перезапись `po/template.pot` и типизированный список спикеров
  `po/template.speakers.mts` (POT_SPEAKERS / PotSpeaker — спикеры POT как
  TS-константа для ревью/маппинга; НЕ путать с CAST_NAMES кастов — они
  рукописные в casts/casts.mts).
- Контексты: `speaker:<Имя>` (define → Display Name, строка, идентификатор),
  `speaker:Narrator` (нарратор — голос, инвариант speaker:* = озвучиваемо),
  `menu`, `speaker-name`, `ui`.
- Метаданные каждой записи: `#. uid:` (md5(msgid)), `#. emotion:` (тон из
  catalog/emotions.json, только speaker:*), `#. arc:` и `#. scene:` —
  выводятся из имён лейблов самой игры (правила potgen, внешних json нет).
  POT — единственная мапа озвучки (сцена → арка → строки): генератор
  раскладывает аудио по `#. arc:` (голосуемая запись без арки → фолбэк
  Other + e2e-гард), рантайм-`label_arc.json` — артефакт сборки из POT
  (задача catalog-legacy-removal, в репе источником больше не является).
- Контроль: e2e-гард — закоммиченный POT обязан байт-в-байт совпадать со
  свежей генерацией (иначе «запусти npm run potgen»).

### Шаг 2 — переводы: POT → po/<lang>.po

- Освежение: `npm run po:update` (порт Neon po_update.py): точный ключ →
  перевод перенесён; ключ исчез, текст жив под другим контекстом → ретаргет;
  текст выпал из POT → запись живёт с флагом `legacy` (human-перевод священен);
  новый ключ → пустой msgstr. Никаких fuzzy-догадок.
- Разовая миграция (впереди): prefill `ru.po` из `tl/ru` до первого апдейта
  игры — точные совпадения + normalizeText-твины + блоклист.

### Шаг 3 — голоса: спикеры POT → мапа голосов

- Спикеров берём ИЗ POT (`msgctxt "speaker:*"` — канонические имена).
- Касты — `casts/` (библиотека голосов: 77 папок = 73 именной + 4 Generic-пула;
  контракт — `{Name}.mts` (cast.types.mts) + ref wav; VOICES-значение `null` =
  папка есть, реф ещё не вылечен).
- Мапа — `casts/casts.mts` (типизированный модуль): `CAST_NAMES` (юнион
  голосов, сверяется с папками в обе стороны), `SPEAKERS` (каждый спикер POT →
  каст | null), `LINE_OVERRIDES` (uid → спикер; перенесены из удалённого
  registry/overrides.jsonl, 23 записи, конвертированы в имена спикеров).
- Ревью/актуализация: `npm run speakers:audit` (рапорт: шаринг голосов,
  null-спикеры, касты без спикеров), `npm run speakers:audit:emit` (блок новых
  спикеров для вставки после апдейта игры), `npm run speakers:check` (тихий
  CI-гейт), `npm run test:speakers` (20 тестов, включая живые гарды).
- Старые реестры who_map.jsonl/overrides.jsonl и их bootstrap удалены
  (2026-10-21) — содержимое живёт в casts.mts.
- Фаза B (впереди): python-пайплайн нативно читает мапу, define уходят из
  yaml/файлов.

### Шаг 4 — каталог: производные джойны

> Переезд на .mts — см. «Направление: плавный переход Python → .mts» ниже.
> Сейчас этот шаг на python (pytest 112 зелёный).

- `python tools/generate/scripts/voice_catalog.py` → `catalog/voices.jsonl`
  (записи uid+who, дифф-манифесты в tmp/voice_delta).
- `catalog/voice_list.json` — рантайм-карта by_who (сборка из кастов).
- `emotion_tag.py` → `catalog/emotions.json` (пофразовые тона для POT).
- Правится только прогоном скриптов, не руками.

### Шаг 5 — озвучка: PO → аудио

- Голосовой пайплайн читает ТЕКСТЫ из PO (ru=msgstr, en=msgid), голоса — из
  casts/ (мапа casts.mts + рефы кастов); файл аудио = `uid__Who.opus`, каталоги `audio/ru`, `audio/en`.
- Озвучка всегда ru + en. **Переозвучка — только по явному гейту владельца**
  («пока всё не починим и не смапим»).

## Обновление игры («вышла новая версия») — последовательность

1. `npm run potgen` — POT перезаписан из новой игры (переводы в POT не живут,
   потеря невозможна по построению).
2. `npm run po:update` — переводы перенесены в новый POT.
3. Проверить дифф: `npm run speakers:audit` — новых/пропавших спикеров,
   протухших LINE_OVERRIDES (переименования видны как «протухший ключ»).
4. Пересобрать производные (шаг 4), если изменилась игра/реестр.
5. Новые/изменённые uid → списки генерации аудио (гейт владельца).
6. Все гейты зелёные.

## Правила репозитория

- Коммиты — ТОЛЬКО по явной прости владельца; владелец ревьюит рабочее
  дерево целиком. В сообщениях коммитов не использовать обратные кавычки.
- Артефакты и черновые скрипты — только `tmp/` этой репозитории (gitignored);
  `~/AppData/Local/Temp/` не использовать.
- JS/новый код = TS (`.mts`, node 24 type-stripping), живут в
  `.opencode/skills/<id>/` + SKILL.md или в `patches/ai-voice-pack/` у своего
  предмета (casts/, po/); тесты — `node --test *.test.mts`. Питон не пишем
  с нуля: только поддержка до порта (см. «ПАМЯТКА: питон мигрирует на TS»).
- md: без таблиц; cspell, markdownlint, prettier — зелёные гейты.
- python: `PYTHONIOENCODING=utf-8`, интерпретатор `/c/Python314/python`.

## ПАМЯТКА: питон мигрирует на TS (инструменты И тесты)

Направление проекта: **всё на TypeScript** (`.mts`, node 24 type-stripping,
тесты — `node --test *.test.mts`). Питон живёт только пока не портирован.

- **Новый код — только TS.** Никакого нового python: ни тулов, ни тестов.
  Нужен питон-инструмент — сначала ищи .mts-аналог, нет → пиши на .mts.
- **Легаси удаляем сразу, переписывание — на TS.** Рассинхронизированный
  питон (мёртвые реестры, устаревшие форматы, дубли старого мира) не висит
  «до лучших времён»: удаляется вместе с тестами/скиллами-описаниями,
  а функциональность переезжает на .mts (пример чистки 2026-10-21:
  who_map/registry → casts/casts.mts + speaker_map.mts).
- **Перенос — волнами, без «большого взрыва»** (гейты обеих сторон зелёные):
  1. порт скрипта на `.mts`;
  2. тесты `.mts` на ТЕ ЖЕ кейсы (`node --test`);
  3. после зелёных .mts-тестов и зелёного pytest на момент удаления —
     питон-скрипт и его pytest-тесты удаляются;
  4. потребители-наследники портируются вслед за своим скриптом.
- **Форматы данных при переносе НЕ меняются** (за исключением явной
  миграции формата, как casts: yaml→mts и texts→{text, emotion_en, emotion_ru})
  — переезжает читающий/пишущий инструмент.
- **Данные тоже едут на TS или умирают.** Рукописные yaml/конфиги мигрируют
  в типизированные `.mts` (casts/{Имя}.yaml → casts/{Имя}.mts, контракт —
  cast.types.mts) либо удаляются, как протухли (нет потребителя ни у рантайма,
  ни у TS-инструментов). Файл без потребителя = легаси = удалить.
- **Уже на .mts**: potgen (+ генерация po/template.speakers.mts), po_update,
  po_core, tlstat, speaker_map (мапа «спикер → голос»: casts/casts.mts),
  cast.types.mts/пофайловые casts/{Имя}.mts, рефы (add_candidate и clean_refs
  с тестами), карта конфигов voice_presets.mts (config.mts, мост
  cast_contract.mts для voice_design), все тесты renpy-po и speaker_map.
- **Пока python (в очереди)**: сборка voice_list → тона/джойны каталога →
  voice_catalog (тяжёлый парсер — последним, станет читать POT, а не rpy);
  остальное по мере касания — каждое касание = повод портировать, а не
  чинить по-старому.
- **Гейты на переходный период**: `npx tsc --noEmit` (типы мапы/кастов),
  `node --test` (TS-тесты), pytest — до удаления перенесённых модулей.
