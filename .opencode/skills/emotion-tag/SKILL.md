# emotion-tag — пофразовый тон диктора

## Что это и зачем

`#. emotion:` в `patches/ai-voice-pack/po/template.pot` — **инструкция диктору**
(CosyVoice instruct2): КАК произносит фразу (тон доставки), а не что в ней
сказано. Ключ — `#. uid:` = md5(msgid), языко-независимый.

```text
#. arc: WarriorPath            ← арка (роутинг аудио в ai_voice/{lang}/{Arc}/)
#. scene: WarriorQueen7Capital ← сцена (таргет --scene при точечной перегенерации)
#. uid: <md5(msgid)>           ← ключ тона и суффикс {uid}__{Who}.opus
#. emotion: Confidently and warmly   ← ТОН (всегда по-английски)
msgctxt "speaker:Sarah"
```

**Поток:** `emotion_tag.mts` (эвристика `RULES` / LLM `--llm-url`) →
`tmp/emotions_tagged.json` (черновик) → `npm run potgen -- --emotions <файл>`
→ **слой `#. emotion_new:` в POT** (overlay поверх roundtrip по uid; действующий
тон = `emotion_new` ?? `emotion`, старый НЕ перетирается — см. «Плавную
миграцию») → `voice_batch.mts` берёт действующий тон из POT.

Приоритет тона в генерации: `--emotion` (CLI) > POT[uid] (действующий =
`emotion_new` ?? `emotion`) > без тона (тогда модель берёт тон из текста
фразы). `--no-emotion` выключает (`_plain`), `--emotion-ru` даёт перевод
для ревью.

## Правила качества тона (ЕДИНСТВЕННЫЙ источник)

1. **Всегда по-английски**, 2–6 слов, одна строка (русские/китайские
   инструкции дают акцент — проверено 2026-09-02).
2. **Состояние диктора при доставке, а не содержание**: «Curiously observing»,
   «In a low menacing whisper» — да; пересказ сюжета, оценка текста,
   цитаты из фразы — нет. Формат — описание, не приказ («Speak angrily» — хуже).
3. **У каждой озвучиваемой записи тон ОБЯЗАН стоять**: `speaker:*` без
   `#. emotion:` = баг генерации (запрещены `none` и пусто). Исключение —
   первичная генерация POT без шаблона.
4. **Тон обязан соответствовать тексту и сцене**: агрессивный текст —
   агрессия; нейтральный + сильная эмоция = вяло. Наррация-наблюдение =
   позиция наблюдателя; реплика = состояние говорящего.
5. **Форма**: с заглавной буквы, без кавычек, без кириллицы/CJK/опечаток
   вроде `Sarа` (кириллическая «а»).
6. **Не шаблонить**: массовый один тон на тысячи разных строк = перекос
   (см. «Аудит»: реальный инцидент — 26 % корпуса «Curiously observing»).
7. В тексте фразы добавляй эмоциональную пунктуацию («Ещё! Ещё!») — но это
   правило перевода/генерации, не тега.

## Аудит качества

```bash
npm run emotion:audit            # отчёт по template.pot: нарушения + однородность
npm run emotion:audit -- --draft # то же для tmp/emotions_tagged.json (ДО overlay)
```

Что смотреть:

- **нарушения формата**: пусто, кириллица/CJK, `none`, >6 слов, 1 слово,
  не с заглавной, кавычки;
- **однородность**: уникальных тонов, топ-тон и его доля, % «один раз»
  (мусорный хвост LLM), доля DEFAULT_EMO.

Контроль после overlay — **e2e-гард** `potgen_e2e.test.mts`: свежий POT
байт-в-байт против закоммиченного; пропажа `#. emotion:` валит тест
(«запусти npm run potgen»).

## Процедура полной переразметки (для агента)

Шаг 1 — **срез до**: `npm run emotion:audit` → цифры (нарушения, топ-тоны).
Шаг 2 — **черновик**: `node patches/ai-voice-pack/tools/generate/scripts/emotion_tag.mts --llm-url http://127.0.0.1:1234 --llm-model qwen/qwen3.5-9b`
(прогон по всем озвучиваемым, пишет `tmp/emotions_tagged.json`;
резюмабелен, каждые 200 строк — чекпоинт; `--dry-run` — только статистика).
Шаг 3 — **валидация черновика**: `npm run emotion:audit -- --draft` —
нарушения формата должны быть 0; массовые перекосы — разобрать вручную.
(Тот же отчёт — это и **статус прогресса**: сколько uid ещё «пусто».)
Шаг 4 — **судья-выборка**: `npm run emotion:judge` (stride-выборка 20 из
черновика, LLM-балл «тон подходит строке/спикеру/сцене», порог 8;
`--pot` — проверить текущий тон POT, `--uid <uid>...` — точечно,
`--n`, `--threshold`, env `LLM_URL`/`LLM_MODEL`). `po:judge` тут НЕ годится —
он судит переводы, а не тон.
Шаг 5 — **применение**: `npm run potgen -- --emotions tmp/emotions_tagged.json` —
новый тон ложится в слой **`#. emotion_new:`**, действующий `#. emotion:`
сохраняется (см. «Плавную миграцию»).
Шаг 6 — **гарды**: `node --test .opencode/skills/renpy-po/potgen_e2e.test.mts`
(байт-в-байт: roundtrip читает ОБА слоя) + `npm run po:check`.
Шаг 7 — **отчёт владельцу**: статистика до/после + ⚠ напоминание:
тон влияет на БУДУЩУЮ генерацию, готовые `.opus` он не меняет — изменения
массового тона = кандидат на перегенерацию (решение владельца).

## Плавная миграция: `emotion` → `emotion_new` (решение владельца 2026-10-26)

Новый тон пишется **рядом со старым**, а не вместо него:

```text
#. emotion: Curiously observing      ← действует для УЖЕ сгенерированного звука
#. emotion_new: Resigned and defiant  ← overlay --emotions; действующий тон
```

- **действующий тон = `emotion_new` ?? `emotion`** — так читают
  `voice_batch.loadCatalog`, `pot_resolve` (промпт/судья po) и аудит;
- **старый слой не трогается** → у готового `.opus` остаётся его тональность,
  сравнение/переход построчный, откат = точечная правка/удаление
  `#. emotion_new:` у конкретной записи;
- **roundtrip обоих слоёв** переживает регенерацию POT (иначе e2e-гард упадёт);
- прогресс перехода виден в `npm run emotion:audit` (блок «миграция
  emotion_new»);
- **окончательный переход** (когда всё перегенерировано и решение владельца):
  переименовать `emotion_new` → `emotion` одной правкой и снять слой —
  до этого момента оба слоя живут вместе.

Однострочная точечная правка тона (без полной переразметки):

```bash
node patches/ai-voice-pack/tools/generate/scripts/emotion_tag.mts --dry-run   # что есть
# правка вручную или --tagged (пере-разметить только уже помеченные)
npm run potgen -- --emotions tmp/emotions_tagged.json
```

## Жизненный цикл (перенесено из renpy-po/SKILL.md, DRY 2026-10-26)

- **Привязка только по uid**: неизменённая фраза переживает обновление игры
  (roundtrip подхватывает тон из предыдущего POT).
- **Фраза изменилась → новый uid → тон сброшен**: навешивается заново вручную
  (или этой процедурой). Автоперенос старого тона на новый uid ЗАПРЕЩЁН.
  Старые uid остаются в шаблоне как безвредные сироты — хранить.
- **`catalog/emotions.json` УДАЛЁН** (2026-10-22, приказ владельца): вторым
  холдом тона был инцидент a16e21ef9 (68 181 запись потеряла тон).
  **Единственный источник тона — `po/template.pot`**, отношение как к данным.
- Частичная разметка (`RULES`-эвристика) оставляет нейтральные фразы без
  тона в черновике — в шаблон они приходят только через roundtrip/overlay.

- **Код**: `emotion_tag.mts` (разметка: `RULES`, `LLM_PROMPT`, `DEFAULT_EMO`),
  `potgen.mts` (roundtrip/overlay), `voice_batch.mts` (потребление тона),
  `emotion_audit.mts` (аудит формата/однородности),

- **Обновление игры** (новые uid без тона ок) —
  `tssr-update-pipeline/SKILL.md` → «Ступень 3».
