# local-dash — пульт «одна страница»

## Зачем

Внутренний статус без Grafana/Prometheus и без сборки: один `.mts` (Node stdlib),
read-only, всё на одной странице с обновлением раз в 2 с. Стоимость
сопровождения — один файл; максимум логики — сбор данных, никаких миграций.

## Запуск

```bash
npm run dash                                              # http://127.0.0.1:8087 + открыть браузер
node .opencode/skills/local-dash/dashboard.mts            # без автооткрытия
node .opencode/skills/local-dash/dashboard.mts --open --port 8099
```

Держать в отдельном окне/фоне. Ctrl+C — остановить. Коммитов/записи в файлы
страница не делает: только читает `po/`, `audio/`, `tmp/translate_queue.json`,
`tmp/translate_<lang>.run.log` и опрашивает порты.

## Что показывает

- **Бэкенд перевода**: `127.0.0.1:8081` (llama-server) + модель; заодно LM Studio
  (:1234) и Strata (:8080) — up/down.
- **GPU**: утилизация, видеопамять, температура (`nvidia-smi`).
- **CPU / RAM**: суммарно по машине.
- **Очередь**: текущий язык, готово/всего, остаток, время последнего обновления
  (`tmp/translate_queue.json`).
- **Языки: текст и озвучка** — ОДНА строка на язык (один и тот же список не
  дублируется двумя карточками): прогресс перевода по `po/<lang>.po` (пустой
  msgstr = не переведено) и рядом прогресс озвучки. Для озвучки: 11 языков
  (список = папки `audio/`, порядок — из `config/language-priority.json`), **план
  у каждого языка свой** — `en` звучится по оригиналу (68 357 реплик), остальные
  только по переведённым строкам, поэтому у языка с 3 % перевода план ~1200, а не
  68 357. Правая колонка — сколько арок закрыто полностью. Ниже: размер корпуса,
  шимы-воркеры (живые процессы инференса), сироты loudnorm и недописанные
  `.part`, сетка арок вида «7/11 яз.» (сколько языков закрыли арку целиком, `✓` у
  всех). Считает **не сама страница**: числа берутся из `voice_status.mts`
  (импорт `voiceLangs`/`countDone`/`plan`/`healthScan`/`activeArcs`), чтобы пульт
  и CLI никогда не расходились.
- **Последнее в прогоне**: последние строки `tmp/translate_<lang>.run.log`.

## Оптимизация (чтобы страница не ела ресурсы)

- `nvidia-smi` — кэш 3 с; `Get-Process` (powershell) — кэш 6 с.
- Счётчики `po` (10 файлов × 15 МБ) и корпус озвучки (~13 тыс. файлов) — **только
  из кэша**: промах отдаётся как `null` (UI пишет «—» / «загрузка…»), а пересчёт
  идёт дольками с уступкой событийного цикла. Оба кэша греются в `start()`.
  Без этого холодный первый запрос висел 8.9 с, тёплый — 0.07 с.
- Обновление страницы — `fetch('/api/state')` раз в 2 с, данных ~3 КБ.
- Пока данных нет — в карточках заглушки «загрузка…»; если `fetch` упал (пульт
  перезапускают) — «нет связи» в заголовке вместо тихого зависания.

## Гарды

`npm run test:dash` — `dashboard.test.mts`: чистая функция `arcsClosed(made, plan)`
(та самая, где был баг приоритета `??`), нулевой план и отсутствие мутаций.
Сервер стартует только при прямом запуске файла (`start()` под гардом
`import.meta.url`), поэтому импорт в тесте порт не занимает.
