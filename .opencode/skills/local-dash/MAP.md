# MAP — local-dash

Факты и грабли (симптом → причина → проверено → что делать).

- **Страница «ест ресурсы» сама** → `nvidia-smi` (~100 мс) и особенно
  `powershell Get-Process` (~300–500 мс) на каждый тик при обновлении раз в 2 с.
  Проверено 2026-11-15. Что делать: кэш в коде — GPU 3 с, процессы 6 с;
  счётчики `po` (файлы по 15 МБ) — 60 с по mtime. Не уменьшать кэш «для
  свежести»: свежесть даёт 2-секундный опрос `/api/state`, а не тяжёлые вызовы.
- **`127.0.0.1` в `fetch`, а не `localhost`** → на Windows `localhost` может
  резолвиться в IPv6 и висеть до таймаута. Проверено на других сервисах
  (2026-10). В коде всюду `127.0.0.1`.
- **`po` считаем «msgid минус один»** → первая запись `msgid ""` — заголовок
  файла, не строка игры. Если не вычесть, проценты врут на 1/69 120 (мелочь,
  но в пульте видно).
- **Очередь показывает «—», хотя прогон идёт** → смотрим не процесс, а
  `tmp/translate_queue.json`; файл пишется только очередью
  (`translate_queue.mts`). Если гоняли `translate_run.mts` вручную — статус
  пустой, это норма (смотреть `tmp/translate_<lang>.run.log`).
- **Порт занят** (`EADDRINUSE`) → уже запущен другой экземпляр пульта; либо
  закрыть его, либо `--port`.
- **Озвучку НЕ считаем на странице руками** → в `tssr-voice-status` прямой
  запрет считать вручную, числа должны совпадать с CLI `voice_status.mts`.
  Проверено 2026-11-16: RU 1397 / EN 1195, Prologue 238/238 — совпало.
  Что делать: пульт импортирует `countDone`/`plan`/`healthScan`/`activeArcs`
  из `patches/.../voice_status.mts` (функции экспортированы, `main` под
  `import.meta.url`-гардом — импорт безопасен). Кэш 60 с: обход корпуса
  - `powershell` для воркеров.
- **`activeArcs()` без запущенных воркеров показывает «арку Other»** → читает
  лог прошлой очереди генерации (`output/voice/gen_all_<lang>.log`) и берёт
  последнюю незакрытую арку. Проверено 2026-11-16. Что делать: пульт рисует
  арку только при `shimWorkers() > 0`.
- **Отчёт по озвучке показывал только RU и EN** → в `voice_status.mts` список
  языков был зашит `["ru","en"]` (легаси прогона CosyVoice), а в `audio/` лежит
  11 языков. Проверено 2026-11-16. Что делать: `voiceLangs()` — папки `audio/`,
  порядок из `config/language-priority.json` (единый источник порядка языков);
  пульт импортирует её же, ничего своего не заводит.
- **«100 % озвучки» у языка с 3 % перевода** → план считался один на всех (по ru,
  68 357). Правильно: `plan(lang)` — `en` по оригиналу, остальные только по
  непустым `msgstr` (озвучивать нечего). Тогда de/ja/fr/pl/ko/it честно
  показывают 100 % (демо-набор озвучен), а es — 1195 из 68 357.
- **`x ?? 0 >= y` считает не то** → приоритет операторов: это `x ?? (0 >= y)`,
  поэтому «арок закрыто» выходило 19/19 даже при 2 % озвучки (поймано на пульте
  2026-11-16). Писать `(x ?? 0) >= y`.
- **Одна вкладка живёт со старым JS** → после правки пульта открытая страница
  показывает «план undefined» / «0 %»: сервер уже отдаёт новые поля, а инлайн-JS
  в браузере старый, и перезапуск сервера вкладку не обновляет. Проверено
  2026-11-16 (владелец поймал дважды). Что делать: в ответе API есть `v`
  (`API_VER`), страница при несовпадении сама делает `location.reload()` (один
  раз за сессию — `sessionStorage`). Поднимать `API_VER` при ЛЮБОМ изменении
  набора полей; вкладку, открытую ДО появления проверки, перезагрузить руками.
- **Неизвестный знаменатель нельзя рисовать нулём** → если `plan`/`total` нет,
  старый `pct(a, b)` возвращал 0 и на экране появлялось «1 195 · 0 %» — враньё
  хуже пустоты. Проверено 2026-11-16. Что делать: `pct` возвращает `null`, UI
  печатает «—» (`P(null)`), ширина полосы = 0.
- **«0 стр/мин» сразу после старта пульта** → сэмпл дельты набирается 30 с,
  до этого скорость неизвестна, а не нулевая. Проверено 2026-11-16. Что делать:
  `rate: null` до первого сэмпла, в UI «…»; настоящий 0 остаётся честным
  сигналом «прогон встал».
- **Счётчик `po` был занижен на 1** → считалось `msgid - 1` минус
  `msgstr "..+`, а у шапки po свой `msgstr ""` и многострочное тело; плюс
  `..+` пропускал переводы из одного символа (`msgstr "A"`). Проверено
  2026-11-16: сверка с `parsePo` дала 69 119 против 69 120. Что делать: резать
  шапку (`text.replace(/^[\s\S]*?\n\n/, "")`) и считать
  `total - count(/^msgstr ""$/)`; сверять с `node scripts/po_check.mts --all`.
- **Импорт `dashboard.mts` занимал порт 8087** → тест ради чистой функции
  (`arcsClosed`) падал с `EADDRINUSE`, потому что сервер стартовал на верхнем
  уровне модуля. Проверено 2026-11-16. Что делать: старт под гардом
  `import.meta.url === pathToFileURL(process.argv[1]).href` (`start()`), тест —
  `npm run test:dash`.
- **`скорость` мигает: число → «…» → число** → скорость считалась ТОЛЬКО в том
  запросе, который перешагнул окно 30 с; остальные 14 из 15 опросов (страница
  стучится раз в 2 с) видели `null`. Проверено 2026-11-16. Что делать: кэшировать
  последнее значение (`rateCache`) и отдавать его, пока не истёк срок/не сменился
  язык.
- **Первый опрос после старта висит ~9 с** → обход корпуса озвучки и разбор
  десяти `po` по 15 МБ синхронные: `setImmediate`-«фон» не спасает, пока работа
  внутри одного куска длиннее паузы — event loop занят. Проверено 2026-11-16
  (замер: 8.9 с первый запрос, 0.07 с тёплый). Что делать: считать дольками по
  языку (`await yieldTick()`), отдавать только кэш (`voiceStatsAsync` /
  `poStats` возвращают `null`, UI пишет «—»), и прогревать кэши в `start()`.
- **Страница выглядела «сломанной», пока грузится** → карточки пустые несколько
  секунд, при перезапуске пульта — навсегда до F5. Проверено 2026-11-16. Что
  делать: в разметке заглушки «загрузка…», при ошибке `fetch` — «нет связи» в
  заголовке; UI не должен молчать.
- **Имя арки в отчёте `voice_status` обрезано до 14 символов** →
  `StoryBeginning` в CLI — это `StoryBeginnings` (15). Сверять по JSON/ключам,
  а не по печатной строке (2026-11-16).
- **Время на пульте шло в двух зонах** → журналы пишутся в UTC (`toISOString`),
  подписи окна резались `.slice(11,16)`, а ETA считался через `getHours()` (уже
  местное). На экране «пасс стартовал 10:38» рядом с «осталось ≈ 13:20» читалось
  как ошибка. Проверено 2026-11-18. Что делать: всё время через `hm()`/`hms()`
  (локальная зона), в подписи окна — «(местное время)»; UTC-срезы не возвращать.
- **Графики здоровья жили в разных окнах** → окно здоровья — последние 240
  замеров (час), а история `-np` берётся целиком (сутки): рядом стояли графики
  с разными шкалами, и метки не сопоставлялись. Проверено 2026-11-18. Что
  делать: точки `-np` клипуются к окну здоровья (`npPts` в `tick()`), значение
  «доигрывается» на оба края окна — режим step это позволяет.
- **Засечки оси времени** — шаг выбирается из круглых минут (`1…720`), не
  больше 5 меток на график; выравнивание по местному смещению зоны
  (`getTimezoneOffset`), иначе при не-целом смещении метки «плывут». Подписи —
  абсолютно позиционированные `span` в `.axis` (совпадают с вертикальными
  засечками в SVG); при сужении карточки `<8 %`/`>92 %` якорь переключается,
  чтобы крайние метки не обрезались (2026-11-18, проверено скриншотом
  Playwright, перекрытий нет).
- **«скорость 0 стр/мин» и «осталось —» при живом прогоне** → скорость мерили
  по опросу страницы (окно 30 с), а цифра `po` приходила из кэша на 120 с: чаще
  всего окно попадало внутрь одного кэша и дельта была нулевой, изредка —
  «прыжок». Проверено 2026-11-19 (it шёл на 2 стр/с, пульт показывал 0). Что
  делать: мерить по ФАКТУ перечитывания файла (`noteProgress`: окно = реальный
  интервал между чтениями), а кэш текущего языка держать коротким (15 с) —
  остальные языки по-прежнему 120 с. Не возвращать «сэмпл по тику страницы».
- **«очередь молчит N мин» сразу после рестарта пульта** → условие было
  `rate === null`, а это значит «сэмпла ещё нет», а не «прогресса нет»; при
  свежем пульте и давно стартовавшем пассе выходило ложное предупреждение.
  Проверено 2026-11-19. Что делать: предупреждать только по измеренному нулю
  (`rate === 0`).
- **Часы в заголовке шли по UTC** (`s.at.slice(11,19)`), а «пасс стартовал» и
  оси графиков — по местному: на экране 04:32 против 07:06. Проверено
  2026-11-19. Что делать: `hms()` для заголовка; UTC-срезы не возвращать.
- **Графики здоровья сжимались в общей полосе** → четыре графика в одной
  карточке `c12`: на узких окнах колонки сжимались до нечитаемых, а метки осей
  налезали друг на друга. Проверено 2026-11-19. Что делать: каждый график —
  своя карточка `c3` (четыре в ряд: мощность, температура, RAM, слоты), под ними
  одна общая строка-легенда на всю ширину (`grid-column:1 / -1`, без рамки).
  Не собирать их обратно в один `#hchart`: минус в том, что заголовок «Здоровье
  ПК» исчезает, — его роль выполняет общая строка под рядом.

- **График скорости «замерзал» и шёл неровными точками** → ряд прогресса
  наполнялся только при запросах страницы: закрыл вкладку — точек нет, открыл
  через час — одна. Проверено 2026-11-19. Что делать: копить прогресс на
  сервере по таймеру (15 с), язык брать из `tmp/translate_queue.json`, а не из
  последнего запроса; при смене языка ряд сбрасывать.
- **Столбики скорости выглядели сплошным блоком** → окно = фактический ряд (2
  минуты после старта), шаг столбика 1 мин → два столбика на всю ширину.
  Проверено 2026-11-19. Что делать: минимум окна 10 минут и шаг столбика из
  ряда `1/2/5/10` мин так, чтобы столбиков было 10–20.
- **Подпись графика скорости налезала сама на себя** → в карточке шириной ~370
  px две подписи «сейчас … стр/мин 08:09» и «за 10 мин 447 строк» не влезают.
  Проверено 2026-11-19. Что делать: короткие подписи («122 стр/мин» и «558
  строк / 10 мин»), подробности — в `title`.

- **У графика скорости нет опоры по вертикали** → линия есть, а сверить её не с
  чем: мгновенную цифру показывает подпись, а «сколько это в масштабе» —
  непонятно. Проверено 2026-11-19. Что делать: горизонтальные пунктиры на
  круглых значениях (50/100/…) с подписями; подписи — HTML-слоем
  (`.yaxis span`), потому что текст внутри SVG с `preserveAspectRatio="none"`
  растягивается по ширине.
- **«100 %» при 14 непереведённых строках** → процент округлялся вверх
  (`Math.round`): 69 106/69 120 = 99.98 → 100.0, кольцо и полоса выглядели
  закрытыми. Проверено 2026-11-19. Что делать: `pct` округляет ВНИЗ до десятых;
  100 % показывается только при полном совпадении.
- **Очередь озвучки не видно на пульте** → карточка показывала только текущий
  `voice_batch`, а Vox-очередь (`vox_queue`/`voxcpm_bench`) не отображалась
  вовсе. Проверено 2026-11-20. Что делать: `voiceQueue()` читает ХВОСТ
  `output/voice/vox_gen_<lang>.log` (96 КБ, не весь: ru-лог 1.2 МБ),
  `parseVoxLog` достаёт последнюю арку и `[i/N]`, «идёт» = лог обновлён < 5 мин.
- **Пульт `voice_ctl status` пишет STALLED, а лог растёт** → пульт смотрит свои
  маркеры и mtime иначе (проверено 2026-11-20: в лог шли строки прогресса, а
  `voice_ctl` показывал «лог 3 ч назад»). Что делать: для «идёт ли» верить
  свежести `vox_gen_<lang>.log` (её и показывает карточка), `voice_ctl` —
  только для старт/стоп.
- **Скорость озвучки скакала (0 → десятки)** → мерили прирост `[i/N]` между
  опросами страницы: окно 3–5 с попадало внутрь одной фразы (фраза ~13 с).
  Проверено 2026-11-20. Что делать: скорость = строки / время с маркера
  `=== START <lang> <arc> HH:MM ===` в логе — средняя за арку, стабильно
  4.4–4.8 реплик/мин; разбор в `scripts/voice_progress.mts` (`logRate`, кэш
  30 с), пульт только читает. Там же «до полной озвучки: N строк ≈ X сут».
- **«Озвучка идёт» при мусоре в audio/** → счётчики считали ЛЮБОЙ .opus:
  легаси-очередь писала туда бенч-имена `{uid}__{voice}__Vox_cfg...`, движок их
  не находит, а пульт/сайт показывали рост (2026-11-20: 1 851 файл в audio/en
  при «прогрессе» 2 998). Проверено. Что делать: `countDone` и
  `catalog_gen.countAudio` фильтруют `parseVoiceName` (только контракт
  `{en12}-{state6} {variant}`); очередь — `voice_ctl vox-start <lang>`
  (= `voice_batch --engine voxcpm2`), `vox_queue` отключён.
- **Скорость и «идёт» по логам разъезжались** → у контуров разные логи
  (`vox_gen_<lang>.log` у легаси, общий `batch.log` у `voice_batch`).
  Проверено 2026-11-20. Что делать: карточка очереди считает ПО КОРПУСУ —
  файлы по контракту, «идёт» = mtime < 5 мин, скорость = файлы за час /
  реальный интервал (`scripts/voice_progress.mts`: `scanCorpus`/`rateFrom`).
- **netstat врёт про живой сервер** → на этой машине пульт, слушающий 8087,
  виден в `netstat -ano` строкой `CLOSED` (и вовсе без `LISTENING`), из-за чего
  `dash:open` считал себя «чужим приложением». Проверено 2026-11-21. Что
  делать: PID слушателя брать из `Get-NetTCPConnection -LocalPort N`
  (`port.mts: listenerPids`), netstat — только фолбэк.
- **ложное «чужое приложение» на холодном старте** → первый `/api/state`
  считает po-статистику по 10 языкам и отвечает дольше секунды; таймаут 1.5 с
  давал отказ. Проверено 2026-11-21. Что делать: таймаут 8 с + второй признак
  «наш» по командной строке процесса (`isDashProcess`).
