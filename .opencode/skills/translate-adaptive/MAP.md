# MAP — translate-adaptive: проверенные факты и грабли

## Что где

| Файл                                  | Роль                                                        |
| ------------------------------------- | ----------------------------------------------------------- |
| `translate_ctl.mts`                   | CLI: status/auto/start/pause/stop/background/turbo          |
| `translate-ctl.cmd`                   | двойной клик: меню для владельца                            |
| `profile.mts`                         | чистая логика профилей (порог, кулдаун) + скорость/ETA      |
| `idle.mts`                            | детектор простоя (разбор вывода)                            |
| `win.ps1`                             | Windows-обёртка: `idle`/`procs`/`stats`/`prio`/`kill`/`sys` |
| `tmp/translate_adaptive/state.json`   | профиль, когда менялся, кулдаун                             |
| `tmp/translate_adaptive/config.json`  | порог/поллинг/кулдаун/turbo/lang                            |
| `tmp/translate_adaptive/samples.json` | история (t, translated) для скорости                        |
| `tmp/translate_adaptive.auto.log`     | журнал watchdog                                             |
| `../translate/backend_wait.mts`       | «бэкенд ушёл → ждать», а не жечь очередь                    |

## Грабли (симптом → причина → проверено → что делать)

1. **Переводчик «мгновенно завершил» 41 486 сбоев за 2 минуты, po не пополнился** →
   при падении порта Strata каждый `fetch failed` закрывал строку как сбой, а
   очередь не останавливалась → проверено 2026-11-14 (первый рестарт Strata при
   смене профиля; в логе `ОШИБКА … TypeError: fetch failed` ×41486 и
   `ГОТОВО: … сбои 41486`) → починено: `call()` в `translate_run.mts` ждёт
   бэкенд (экспоненциально до 30 с, максимум 45 мин, env `TSSR_BACKEND_WAIT_MS`)
   и повторяет ТУ ЖЕ строку (`translate/backend_wait.mts` + тест).
   **Не «оптимизировать» это назад в один fetch.**

2. **`--pool-cores 0-15` не ускоряет: движок пишет `ignoring --pool-cores … (not
an option of this engine)`** → флаг есть в `strata launch --help` и в
   `serve/server.py`, но конкретный билд движка 0.1.55 его не знает (флаг
   уезжает в `strata.exe`, а тот его не принимает) → проверено 2026-11-14 по
   `engine.log` → удвоения пула CPU-экспертов (SMT) на этом билде НЕТ; не
   добавлять флаг в профили, не искать «ускорение» в потоках.

3. **`--parallel 8` не даёт скорости** → узкое место — пул CPU-экспертов
   (8 потоков, «the rest of a batch of <= 128 rows on 8 CPU threads»), а не
   слоты; слотов 2 хватает: 8 клиентских запросов идут 4 волнами, ответы
   6–32 с против таймаута 120 с → проверено 2026-11-14 → turbo по умолчанию
   `soft` (только приоритеты), `hard` — экстренный рычаг, не дефолт.

4. **RAM у 35B-модели на пределе** (18.75 ГБ экспертов в pageable host-памяти;
   свободно 0.6–2.5 ГБ из 31) → любое повышение параллелизма увеличивает
   давление и риск подкачки → проверено 2026-11-14 (замеры A/B) → в turbo не
   поднимать слоты без свободной RAM ≥ 3 ГБ.

5. **`query user` для простоя не годится** → вывод локализован (cp866, «Активен»
   вместо числа) и гранулярность 1 мин → проверено 2026-11-14 → используем
   `GetLastInputInfo` (win.ps1, `IDLE_MS`), он же источник «Времени простоя» в
   диспетчере задач.

6. **`GetLastInputInfo` + `Environment.TickCount` через 49.7 суток** → int32
   переполняется → в `win.ps1` вычитание сделано в `unchecked uint`
   (`tick - l.dwTime`) → держать так; проверено на живом вызове (idle 0…N с).

7. **Один PowerShell-вызов ≈ 0.4 с** → опрос простоя раз в 20 с стоит ~2 %
   одного ядра; для 15-минутного порога это норм (проверено 2026-11-14).
   Не опускать `--poll` ниже 10 с — начнёт быть заметно, выигрыша нет.

8. **Нельзя `taskkill /IM node.exe`** → рядом живут node-процессы opencode/MCP →
   убиваем только найденный по командной строке `translate_run.mts`
   (`win.ps1 -Cmd procs` + regex) → правило репозитория, проверено.

9. **Strata перезапуск ≈ 90–150 с** (у `--parallel 8` дольше: 8 слотов KV =
   6 ГБ VRAM, дольше грузится) → поэтому `hard` дорог и почему `soft` —
   дефолт; кулдаун входа в turbo существует именно из-за этой цены.

10. **`status` не показывал скорость сразу после старта** → скорость считается
    по истории сэмплов и требует ≥ 60 с между крайними (иначе `—`) → это
    ожидаемо, не баг: подождать минуту или посмотреть `СЦЕНА/СТАЛО` в логе.

11. **`state.json` не создавался до первого переключения** → `status` показывал
    0 мин в профиле → добавлено: `loadState()` создаёт файл при первом
    обращении → проверено 2026-11-14.

12. **Изменение конфига Strata (`--parallel`) требует рестарта** → API менять
    слоты на ходу не умеет → поэтому `soft`-turbo не трогает бэкенд вообще
    (только приоритеты процессов), а `hard` честно платит простоем.

13. **`spawnSync powershell ETIMEDOUT` при успешном запуске** → `execFileSync`
    ждёт EOF пайпа, а пайп держат живые потомки (Strata: `strata_control.runtime`
    - движок; watchdog-детач: сам node) → проверено 2026-11-14 дважды
      (Strata-перезапуск и `auto --detach`; в обоих случаях процесс стартовал,
      а инструмент падал) → **любой запуск «в фон» делать с `stdio: "ignore"`**,
      а PID узнавать из файла (`tmp/translate_adaptive/watchdog.pid`).

14. **Владелец физически за ПК → простой не растёт** (ввод каждые 1–2 с) → E2E
    переключения на живом человеке не воспроизводится → добавлен тестовый хук
    `TSSR_IDLE_SEC=<сек>` в `readIdleSeconds` (в обычной работе не выставляется)
    → проверено 2026-11-14: `TSSR_IDLE_SEC=1200 auto --run-min 1` → turbo за
    2.9 с (все три процесса AboveNormal), `TSSR_IDLE_SEC=0 auto --once` →
    background за 2.9 с (BelowNormal/Normal/Normal).

15. **`--run-min`** — watchdog на N минут: нужен для калибровки и проверки на
    живой системе, иначе `auto` крутится вечно и его надо убивать руками.
