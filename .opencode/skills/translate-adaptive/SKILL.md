# translate-adaptive — перевод, который уступает ПК владельцу

Когда использовать: идёт долгий перевод (`translate_run.mts <lang>`, часы/сутки)
и нужно, чтобы он **не мешал работать за компьютером**, но использовал
ресурсы, когда владелец отошёл. Также — когда нужно посмотреть «сколько
осталось» и мгновенно всё выключить.

Профиль выбирается по **простою пользователя** (Windows `GetLastInputInfo` —
то же «время простоя», что в диспетчере задач).

## Команды

```bash
CTL=.opencode/skills/translate-adaptive/translate_ctl.mts

node $CTL status                 # профиль, простой, PID, скорость, ETA, CPU/GPU/RAM/VRAM
node $CTL status --json          # то же машинно (для замеров/скриптов)

node $CTL start                  # запустить перевод в текущем профиле
node $CTL auto --detach          # watchdog: сам держит профиль по присутствию
node $CTL auto --once            # один такт (понять, что он решил бы)
node $CTL auto --run-min 2       # watchdog на N минут (калибровка/тест)
node $CTL watchdog-stop          # остановить watchdog

node $CTL pause                  # пауза: убить переводчик, Strata оставить
node $CTL stop                   # СТОП ВСЁ: переводчик + Strata (освободить VRAM/RAM)

node $CTL background             # принудительно щадящий (напр. перед игрой)
node $CTL turbo                  # принудительно turbo
```

Двойной клик: **`translate-ctl.cmd`** — меню (статус + старт/авто/пауза/стоп/turbo/background).

Настройки живут между запусками (`tmp/translate_adaptive/config.json`):

| Флаг                      | Дефолт | Смысл                                    |
| ------------------------- | ------ | ---------------------------------------- |
| `--idle-min N`            | 15     | сколько минут без ввода = «отошёл»       |
| `--poll S`                | 20     | период опроса watchdog                   |
| `--cooldown-min N`        | 15     | не входить в turbo чаще, чем раз в N мин |
| `--turbo soft\|hard\|off` | soft   | чем turbo (см. ниже)                     |
| `--lang zh`               | zh     | какой язык переводим                     |

## Профили (замеры 2026-11-14)

|                            | background       | turbo                             |
| -------------------------- | ---------------- | --------------------------------- |
| когда                      | владелец за ПК   | владельца нет ≥ 15 мин            |
| переводчик (`node`)        | BelowNormal      | AboveNormal                       |
| Strata server + engine     | Normal           | AboveNormal                       |
| Strata `--parallel`        | 2                | 2 (soft) / 8 (hard)               |
| скорость (реальные строки) | **26.9 стр/мин** | 29.4 стр/мин (hard) / 26.9 (soft) |
| RAM свободно               | 0.6–2.5 ГБ из 31 | —                                 |
| VRAM                       | 15.5/15.9 ГБ     | —                                 |

**Почему turbo «мягкий».** Узкое место — пул CPU-экспертов Strata (8 потоков,
это видно в стартовой строке движка), а не число слотов: 8 слотов дают всего
**+9 %** (26.9 → 29.4 стр/мин, на грани шума). Удвоить пул через
`--pool-cores 0-15` **нельзя** — движок 0.1.55 молча игнорирует флаг («not an
option of this engine»). Значит единственный бесплатный рычаг — приоритеты:
когда владелец работает, они уводят модель назад (в этом и смысл background),
когда никого нет — приоритеты ничего не отнимают, и «ускорение» честно ≈ 0, но
и платить за него нечем (0 с простоя).

hard (`--turbo hard`) — рычаг «ушёл на ночь»: рестарт Strata с `--parallel 8`
за ~2 мин на входе и ~2 мин на выходе. Прибавка 9 % отбивает эти 4 минуты
только при отсутствии **≳47 мин**; плюс GPU греется до 60 °C и 6 ГБ VRAM уходит
под KV. Поэтому дефолт `soft`, а hard включается явно (`--turbo hard`).

## Как переключается

- **Владелец вернулся → background немедленно** (следующий такт watchdog,
  ≤ `--poll` ≈ 20 с). Это приоритеты: мгновенно, без рестартов, без потерь.
- **Владелец отошёл → turbo** только после `--idle-min` простоя **и** если
  с прошлого выхода из turbo прошло ≥ `--cooldown-min`. Это гистерезис: пара
  «ушёл на 16 минут → вернулся» не вызывает двух дорогих переключений.
- Перед дорогим (hard/turbo) переключением простой перепроверяется ещё раз.
- Если детектор не ответил (нет PowerShell, не интерактивная сессия) — профиль
  **не меняется** (не гадаем).

## Безопасность

- `stop` гасит переводчик **по PID, найденному по командной строке**
  (`node … translate_run.mts`), никогда не «все node.exe»: чужие процессы
  (opencode, MCP) не трогаются.
- Strata гасится своим же CLI (`strata.py launch --stop`), а не `kill`.
- Перевод резюмабелен: прогресс — `po/<lang>.po` (непустые msgstr) +
  `tmp/translate_<lang>.done`. После `pause`/`stop` достаточно `start`.
- Рестарт бэкенда больше **не сжигает очередь**: `translate_run.mts` на сетевых
  ошибках ждёт бэкенд до 45 мин (`TSSR_BACKEND_WAIT_MS`) и повторяет ту же
  строку (см. `translate/backend_wait.mts`, инцидент 2026-11-14).

## После ребута / первый запуск

```bash
node .opencode/skills/translate-adaptive/translate_ctl.mts start          # поднимет и Strata, и перевод
node .opencode/skills/translate-adaptive/translate_ctl.mts auto --detach  # включит адаптивность
```

`start` сам поднимает Strata в текущем профиле (~1–2 мин), если она не запущена
(после `stop` или ребута), — иначе переводчик стоял бы в `[BACKEND-DOWN]`.
Watchdog ребут не переживает (это обычный процесс): после загрузки — та же
команда `auto --detach`.

## Тесты

```bash
node --test .opencode/skills/translate-adaptive/idle.test.mts \
            .opencode/skills/translate-adaptive/profile.test.mts \
            .opencode/skills/translate/backend_wait.test.mts
```

Покрыто: разбор `IDLE_MS`, «детектор молчит → профиль не дёргаем», порог,
кулдаун, немедленный выход из turbo, `--turbo off`, скорость по окну сэмплов,
ETA, решение «ждать бэкенд» (сеть vs. ответ модели vs. предел ожидания).

## Замеры (2026-11-14, реальный прогон zh, 7800X3D / 32 ГБ / 5070 Ti 16 ГБ)

Считаются **реально переведённые строки** (непустые `msgstr` в `zh.po`), окно
6–7 минут, тот же поток работы.

| Конфиг                                               | Строк/мин          | CPU всего        | GPU               | VRAM              | RAM свободно  |
| ---------------------------------------------------- | ------------------ | ---------------- | ----------------- | ----------------- | ------------- |
| background: `--parallel 2`, pool 8, prio BelowNormal | **26.9**           | 7–89 % (рывками) | 27–67 %, 41–46 °C | 15.5/15.9 ГБ      | 0.6–2.5 ГБ    |
| turbo-hard: `--parallel 8`, pool 8, prio AboveNormal | **29.4**           | 6–68 %           | 14–72 %, 44–60 °C | 15.1–15.7/15.9 ГБ | 0.7–2.3 ГБ    |
| turbo-soft: та же Strata, только приоритеты          | = background ± шум | без изменений    | без изменений     | без изменений     | без изменений |

Читать так: **8 слотов дают +9 %** — это на грани шума (длина строк в корпусе
гуляет сильнее), и цена у него не нулевая: ~2 мин простоя Strata на входе и
столько же на выходе, плюс GPU греется до 60 °C и в VRAM уходит 6 ГБ под KV.
Окупается при отсутствии **≳47 мин** (прикидка: `(T−4)·29.4 > T·26.9` → T > 47).
Поэтому дефолт — `soft` (ноль простоя, ноль риска), а `hard` оставлен на
«ушёл на ночь» и на другое железо.

Почему нет «настоящего» turbo: узкое место — пул CPU-экспертов (8 потоков),
`--pool-cores` этот билд движка игнорирует, а RAM у 35B-модели и так на пределе
(свободно 0.6–2.5 ГБ из 31: 18.75 ГБ экспертов в pageable host-памяти).
Поднимать параллелизм дальше — значит повышать риск подкачки без выигрыша.
