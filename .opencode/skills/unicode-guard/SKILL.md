## What I do

Нахожу в исходниках символы, которые визуально неотличимы от ASCII или невидимы,
но ломают поиск/линт/безопасность.

### Проблема

VS Code подсвечивает символы фразой "This character could be confused with the
ASCII character" (настройка `editor.unicodeHighlight.ambiguousCharacters`).
Классические случаи в этом репо:

- кириллическая «а/е/о/с/х/у» внутри латинского слова (и наоборот) — из-за
  автодополнения/копипаста из переводов;
- NBSP (U+00A0) вместо обычного пробела — «прилипает» слова, ломает поиск;
- невидимые ZWSP/ZWNJ/BOM — портят строки uid/md5, ломают сравнение;
- типографский апостроф ’ (U+2019) внутри латинского слова (`don’t` вместо
  `don't`) — ломает regex/поиск.

ВАЖНО: выбор между «е» и «ё» (и любыми другими вариантами одной буквы)
РЕШАЕТСЯ ПО СЕМАНТИКЕ слова в предложении, а не по какому-либо списку.
Сканер НЕ флагает е/ё — это задача ревьюера/переводчика.

### Решение

Скрипт `scan_confusables.mts` (ТОЛЬКО читает, ничего не правит):

1. **CONFUSED / MIXED_SCRIPT** — слово из букв двух скриптов. CONFUSED —
   латинское слово с кириллическим lookalike (то самое предупреждение VS Code);
   MIXED_SCRIPT — смесь без явного доминанта.
2. **INVISIBLE** — ZWSP/ZWNJ/ZWJ/WJ/BOM/soft-hyphen, bidi-контролы.
3. **NBSP** — неразрывный пробел.
4. **TYPO** — типографский апостроф ’ в латинском слове.

Escape-последовательности (`\n`, `\uXXXX`) маскируются до анализа —
`"текст\nХарактер"` НЕ считается смешанным словом (регрессия, покрыта тестом).

## Использование

```bash
# Сканировать файл(ы) или каталог(и)
node .opencode/skills/unicode-guard/scan_confusables.mts <path> [more...]

# Машинный вывод (для оркестрации)
node .opencode/skills/unicode-guard/scan_confusables.mts --json <path>

# Тесты сканера
node --test .opencode/skills/unicode-guard/scan_confusables.test.mts
```

Exit code: 0 — чисто, 1 — есть находки (CI-гейт), 2 — неверный usage.

Сканируемые расширения: .mts/.cts/.mjs/.cjs/.js/.ts/.tsx/.jsx/.rpy/.json/.md/
.yml/.yaml/.txt/.cfg/.py/.sh/.cmd. Пропускаются node_modules, .git, dist,
**pycache**, .cache.

## Правила правок (ОБЯЗАТЕЛЬНО)

1. **Никаких автозамен и циклов по файлам** — только точечные правки найденных
   мест, по одному.
2. Каждую правку сверять по контексту предложения (в т.ч. е/ё — по семантике).
3. После правок — повторный прогон сканера + `npm run typecheck`.

## Если VS Code подсвечивает весь русский текст

Это НЕ проблема файла. Лечение — настройка VS Code (не трогаем исходники):

```jsonc
// settings.json
"editor.unicodeHighlight.allowedLocales": { "ru": true }
```

Проверить файл перед выводами: `node .opencode/skills/unicode-guard/scan_confusables.mts <file>` —
чисто → подсветка редактора, а не баг исходника.
