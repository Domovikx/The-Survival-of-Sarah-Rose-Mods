# Статус генерации озвучки TSSR

ЕДИНЫЙ тул для статуса/прогноза — не считай вручную (find/wc/grep по ai_voice — нет, это дублирование и ошибки).

> **Движок генерации с 2026-11 — VoxCPM2 (единственный; ветка CosyVoice3
> удалена 2026-11-21).** Прогоны идут через `voice_batch.mts --engine voxcpm2`
> с общим логом `batch.log` — «что сейчас идёт», прогресс/ETA, пауза/стоп —
> ПУЛЬТОМ (`voice_ctl.mts status`, раздел «Контур VoxCPM2» внизу). Тул
> `voice_status.mts` ниже — счётчик корпуса (готовые файлы, %, арки, размеры);
> живую арку он берёт из per-language лога, поэтому для статуса прогона
> источник истины — пульт.

## Когда вызывать

Пользователь спрашивает:

- «статус?», «как идёт генерация?», «сколько готово?», «прогноз?», «когда закончится?»
- «какие арки готовы?», «что сейчас генерится?»
- «проверь здоровье» (воркеры, tmp-сироты)

## Команда

```bash
node tools/generate/scripts/voice_status.mts       # полный отчёт + замер (~70 с)
node tools/generate/scripts/voice_status.mts --fast  # быстро (~6 с), без замера
node tools/generate/scripts/voice_status.mts --arc Other        # точечно: по конкретной арке
                                                #   (RU/EN, по голосам, размер)
node tools/generate/scripts/voice_status.mts --char Sarah       # точечно: по персонажу
                                                #   (план фраз, сделано, по аркам)
node tools/generate/scripts/voice_status.mts --detail           # подробный: арки×проценты×размер,
                                                #   топ голосов, вокеры, сироты
```

(Тул портирован на TS 2026-10-22; python voice_status.py удалён как легаси —
семантика команд и флагов та же.)

## Что выводит тул

- План: 134 534 фразы (67 267 озвучиваемых × RU+EN)
- RU/EN: сколько готово (стемы `.opus`/`.wav` — сейчас в корпусе только opus; пара wav+opus = один), %, размер (оба формата)
- Арки: сделано/всего, завершённые помечены ✓
- Вокеры: число voice_batch-процессов (node), активная арка (из per-language лога `vox_gen_<lang>.log`)
- Здоровье: tmp-сироты loudnorm (_.ln.tmp.wav — мусор от kill; с 2026-10-14 в ai_voice только opus, легаси-wav удалены, поэтому таких сирот не бывает) и недописанные_.part (обрыв конверта, атомарная запись — финалы целы)
- Скорость (замер прироста 60 с) → фраз/час, остаток, прогноз в часах/днях

## Как интерпретировать

- **Активная арка**: последняя START-метка в `output/voice/vox_gen_<lang>.log` без DONE после неё
- **Скорость** волатильна (CPU делится с игрой/системой) — прогноз ориентировочный
- **tmp-сироты** появляются при kill/ребуте в окне ffmpeg→os.replace; финальные wav при этом НЕ страдают — это выяснено 2026-09-05. С 2026-10-14 новые файлы пишутся сразу в opus (`.part` → rename), а легаси-wav из ai_voice удалены — сироты `.ln.tmp.wav` там невозможны
- **Смешанный корпус** (легаси-wav + opus) считается корректно на случай возврата: стем с любым из расширений = одна готовая фраза; двойного счёта нет. Сейчас корпус — только opus
- Ускорение: добавить воркеры (до 4), но CPU забивается; или резать по аркам (`--arc`)

## Контекст

Очереди: `voice_batch.mts --engine voxcpm2 --lang <l>` — старт только через пульт
(`voice_ctl.mts start <lang>`, 11 языков, resumable, низкий приоритет).
Логи: `output/voice/batch.log` (общий прогресс/ETA). Рестарт после ребута — см. AGENTS.md.

## Контур VoxCPM2 (ЕДИНСТВЕННЫЙ, все языки, 2026-11)

**Генерация полностью на VoxCPM2** — ветка CosyVoice3 удалена 2026-11-21
(`cosyworker.py`, `voice_queue.sh`, cosy-очереди и обёртки `voice-*.cmd`).

- Запуск: `node tools/generate/scripts/voice_batch.mts --engine voxcpm2 --lang <l> --demo`
  (демо-скоуп = 1188 игровых фраз + 7 витринных = 1195 файлов на язык; без
  `--demo` — полный проход; старт канона — пультом `voice_ctl.mts start <lang>`).
- Полный проход EN = **68 357 реплик**. Замер канона
  (`voice_batch --engine voxcpm2`, имена по контракту `{en12}-{state6} {variant}`)
  на живом прогоне 2026-11-20: **4.4–4.9 реплики/мин** (≈13 с на фразу, после
  прогрева модели) → **≈10–11 суток** непрерывной работы GPU.
- Легаси-очередь `vox_queue` (она звала `voxcpm_bench`) ОТКЛЮЧЕНА 2026-11-20:
  писала в корпус имена бенча `{uid}__{voice}__Vox...`, которые движок не
  находит. Скорость та же, результат — невидимый. Гейты и разбор —
  `docs/voice-naming.md` («Гейты», «Инцидент 2026-11-20»).
  Публичный снимок прогресса (лендинг): `node scripts/voice_progress.mts` —
  пишет `site/src/shared/config/voice-progress.generated.ts`; счётчики —
  `voice_status.mts`, скорость — mtime файлов корпуса (только по контракту).
- **Файл в audio/ по имени НЕ по контракту = файла нет** для игры. Проверка
  перед выводом цифр: `parseVoiceName(name) !== null`.
- Лог ОБЩИЙ на все языки: `output/voice/batch.log` (не `vox_gen_*.log`!).
  Прогресс — строки `HH:MM:SS [n/m] uid Arc Who: ...`, свой прогноз — в строках
  `saved ... eta ~N мин`. Замер скорости: ~215–250 фраз/час.
- Статус/пауза/стоп — пульт `node tools/generate/scripts/voice_ctl.mts status`
  (подхватывает `voice_batch.mts --engine voxcpm2 --lang <l>`, показывает
  арку/прогресс/ETA из batch.log; пауза/стоп — `voice_ctl.mts stop|pause|resume <lang>`,
  алиасы `vox-stop|vox-pause|vox-resume`). Ручной подсчёт файлов — не нужен.
- `voice_status.mts` (тул выше) — счётчик корпуса (готово/%/арки/размеры);
  для статуса текущего прогона источник истины — пульт + batch.log.

## Сторож прогона (когда просят «последи за озвучкой»)

```bash
node .opencode/skills/tssr-voice-status/voice_guard.mts --lang en --minutes 5 --for 60
```

Каждые N минут: считает готовые файлы (`countDone`), проверяет процесс через
пульт. Мёртвый процесс — поднимает (`voice_ctl vox-start <lang>`, прогон
resumable); три проверки без прироста — считает зависанием и перезапускает.
Лог: `tmp/voice_guard.log` (и stdout, если гоняешь в фоне).

Порог «нет движения» — 3 проверки, чтобы не дёргать GPU из-за медленной арки:
VoxCPM2 может отдавать 2–4 реплики в минуту, и это нормально.

## Адаптивный режим: ушёл — полная загрузка, вернулся — экономный

```bash
npm run voice:adaptive        # --idle 900 --poll 60 по умолчанию
```

Сторож смотрит простой Windows (`GetLastInputInfo`):

- **нет ввода ≥ 15 мин** → перезапускает `voice_batch` с **двумя воркерами**
  (~15.3 ГБ VRAM, +47–76 % темпа по замерам 2026-11-21);
- **вернулся к ПК** (ввод был за последние 15 мин) → один воркер, ПК отзывчив;
- процесс `voice_batch` умер — поднимает заново; переключения чаще, чем раз
  в 15 с, не делает.

Останавливается флагом `tmp/voice_adaptive.stop` (или убить процесс). Пульт
показывает такой прогон как RUNNING: voice_batch без флага движка — уже VOX
(CosyVoice3-контура больше нет).

## Пауза на несколько дней (ПК нужен другому агенту)

Полная остановка — БЕЗ автозапуска:

```bash
echo stop > tmp/voice_adaptive.stop            # сторож выйдет и не поднимет батч
# либо: npm run voice:resume:stop
```

Проверить, что тихо: `voice_ctl status` → EN STOPPED, `nvidia-smi` → ~1–2 ГБ.
Сторож с `--start-at HH:MM` сам поднимется в назначенное время (тихий режим),
но на несколько дней его лучше просто не запускать.

Чек-лист возобновления и состояние прогресса — `tasks/2026-11-22-voice-resume.md`.
