# po-audit — аудитор переводов

Главная цель (идея владельца 2026-10-25): **найти, в чём лажа** в уже
переведённом — не переводить заново, а диагностировать и **возвращать
ошибочные записи на перевод**. Рассчитан на запуск сабагентом поверх
прогонов `po:translate`.

## Источник правды — один

Все классы (кроме E — он живёт только в аудиторе, а в переводе его ловит
`judge LANGUAGE GATE`) завязаны на авточеки `po_translate.mts`
(`checkTranslation`, `isSymbolicMsgid`, `foreignScriptIssue`): правило,
пойманное при переводе, тем же правилом ищется в готовом файле. Новый класс
добавляется ОДНУДУ: в `po_translate.mts` (авточек, тест) + в `po_audit.mts`
(класс, действие) — тогда он и предотвращает, и находит.

## Классы аномалий

| Кл    | Что                                                                | Реальный кейс                                                                                             | `--fix`                  |
| ----- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- | ------------------------ |
| **A** | символьный msgid ≠ идентичность — галлюцинация модели по контексту | `msgid "<"` → `<A Brief Investigation on Ethics>` (pl), `《伦理学简史》作者：路凡` (zh), `< ui >` (de/it) | `msgstr = msgid`         |
| **B** | msgstr == msgid с буквами                                          | ru `Ctrl`, `Enter`, `Page Down` — **это и есть перевод**                                                  | только отчёт             |
| **C** | чужая письменность (кириллица в латинских, CJK в ru, миксы)        | pl `Thomas`→`Томас`; es `retuercе` (кириллическая «е» внутри слова); ko смешал хангыл с кириллицей        | `msgstr=""` → на перевод |

> **ЗАПРЕТ владельца (2026-10-26):** класс D («короткий msgid → длинный
> перевод») и ЛЮБЫЕ сравнения длины msgstr с msgid удалены и не должны
> возвращаться. Длина не влияет на качество — строка любой длины нормальна,
> если перевод верен. Смысл/полноту проверяет только LLM-ревьюер (судья).
>
> Удалён и класс E (триграммный детектор чужого языка): математика вместо
> смысла. Чужой язык (испанский в it/de/fr/pt, немецкий в pl) ловит теперь
> **только LLM-судья** (`judge LANGUAGE GATE` — при переводе) и ревьюер/агент
> (этот скилл — для уже переведённого). Автоматических классификаторов языка
> больше не будет.

Пустые `msgstr` НЕ аудируются — их ведёт очередь `po:translate` (плюс шлюз
символьных msgid в ней сам выравнивает A-класс без LLM при старте прогона).

## Команды

```bash
npm run po:audit                     # отчёт по всем 10 языкам (EN vs TR)
npm run po:audit -- --lang es        # один язык
npm run po:audit -- --fix            # применить: A -> идентичность, C/D -> пусто
npm run po:audit -- --json           # JSON для сабагента/скриптов
node .opencode/skills/renpy-po/po_audit.mts --help
```

## Правила безопасного применения

1. **`--fix` ТОЛЬКО когда прогон этого языка не идёт** — иначе работающий
   `po_translate` перезапишет файл своим кэшем и фикс пропадёт.
   Проверка: `npm run po:translate:status` (строка `ИДЁТ`), pid-файлы
   `tmp/po_translate_<lang>.pid`.
2. C/D после `--fix` становятся **пустыми** → попадают в ближайший прогон
   (`es-tail` покрывает всё es, UI-ретраи — `menu,ui,speaker-name`).
   Если нужного прогона не будет — догони явно: `npm run po:translate -- --lang <code>`.
3. **B не чинить автоматом** — это осознанные совпадения (клавиши, имена).
   Ручной разбор: если копия англ. реплики — это бага, чисти руками.
4. `--fix` меняет po-файлы → перед коммитом: `npx oxlint`/`node --test` не
   требуются (po — данные), но `git diff` посмотреть обязан.

## Ручная/семантическая часть (скилл-аудитор, этап 2)

Авточеки ловят ТОЛЬКО формальные классы. Цель скилла шире — «в чём лажа»
по смыслу. Сабагент поверх прогонов дополнительно:

1. Берёт `--json` отчёт + свежие `tmp/po_translate_<lang>.jsonl`
   (`rejected: true` с `issues` — готовые замечания судьи);
2. Для каждой записи показывает **EN vs TR** и решает: реальная ошибка
   перевода (род, регистр, смысл, пропущенное) или ложная тревога судьи;
3. Реальная ошибка → вернуть на перевод: `msgstr=""` в po-файле (тем же
   ключом, что `--fix`) + запуск доборки этого языка;
4. Отчёт в журнал задачи: сколько нашли, сколько ложных срабатываний.

Эталонные правила качества — скилл `skill-translate-rpy`/`renpy-po`
(согласование рода, 18+ регистр, стилистика). Спорные случаи — НЕ чинить
самому, а вынести владельцу списком EN vs TR.
