# MAP — translate (построчный перевод)

Факты и грабли, проверенные практикой. Формат: симптом → причина → проверено → что делать.

- **`po/<lang>.po` стал нулями (размер есть, содержимого нет)** → процесс
  перевода убили посреди записи (перезапуск сервера/сессии, kill), и запись шла
  НЕ через `writePoAtomic` (или через сторонний writer). Проверено 2026-11-15:
  `zh.po` = 11 102 280 байт нулей, 0 msgid. Что делать: `git status` покажет
  файл как изменённый → `git checkout -- patches/ai-voice-pack/po/<lang>.po`
  (в HEAD всегда целая версия), затем `npm run po:check`; незакоммиченный
  прогресс при этом теряется — поэтому после каждого крупного батча делай
  коммит `chore(po): <lang> — прогресс N/M`.
- **`grep -c '^msgstr ".\+'` врёт, что «переведено всё»** → в BRE `.` совпадает
  с закрывающей кавычкой, поэтому пустой `msgstr ""` тоже считается (2026-11-15
  этой проверкой пустые de/es/fr/it/ja/ko/pl/pt выглядели полными) → считать
  через `node scripts/po_check.mts --all` (он печатает «пустых N») или
  `grep -c '^msgstr ""$'`; на глаз — именно пустые, не непустые.
- **После `git checkout -- po/<lang>.po` `npm run po:check` пишет «файлов
  к проверке нет»** → проверяются только ИЗМЕНЁННЫЕ против HEAD файлы, а
  восстановленный файл байт-в-байт равен HEAD → для проверки восстановленного
  звать `node scripts/po_check.mts --all` (2026-11-15: 10 файлов целы).
- **`tmp/translate_<lang>.done` после аварии забит нулями и обрезан** (проверено
  2026-11-15: 17 КБ нулей, 53 339 строк против 54 683 заполненных в po) → чинить
  не нужно: `po` — источник истины, `done` только кэш (пропуск идёт и по
  непустому `msgstr`); прогресс/скорость смотреть `translate_ctl status`.
- **Перевод ушёл на общую модель (Strata/Qwen3.6) вместо переводческой** → раннер
  брал бэкенд из пульта (`resolveBackend()`), а пульт переключали под чат/эмоции.
  Проверено 2026-11-15: прогон `zh` дошёл до 94 % на `qwen3.6-35b-a3b-ud-q4_k_xl`.
  Что делать: перевод и судья теперь зовут `resolveTranslateBackend()`
  (`translate_backend.mts`) — дефолт `index-translate-9b` в LM Studio `:1234`,
  пульт на них не влияет; оверрайд только `--model`/`--base-url` или env
  `TSSR_LLM_MODEL`/`TSSR_LLM_URL` (+ `⚠ НЕ переводческая модель` в шапке).

- **Почему перевод вообще оказался на Strata (первопричина 2026-11-15)**: и
  `translate_run`, и судья, и правки регистра (`tone_fix`/`tone_native`) брали
  бэкенд из пульта (`resolveBackend()`), а пульт с 2026-11-01 по умолчанию —
  Strata (`qwen3.6-35b…`). Достаточно было один раз не переключить пульт.
  Убито в корне: все переводные тулы зовут `resolveTranslateBackend()`
  (дефолт `index-translate-9b`), в раннере — STOP на не-переводческой модели,
  **обходного флага нет**. Проверка: `TSSR_LLM=strata` больше не влияет
  (2026-11-15), `TSSR_LLM_MODEL=qwen3.6…` → STOP. На пульте остались только
  эмоции (`emotion_tag`/`emotion_judge`) — это не перевод.
