# translate — построчный перевод (с нуля)

## Как устроен перевод

- **Построчно:** одна строка = один перевод. Переводится только целевая строка.
- **Контекст:** перед строкой модели даются **3 реплики ДО** и **1 ПОСЛЕ**
  (если они есть) — они нужны, чтобы понять ситуацию, а не для перевода.
- **Сначала ресёрч, потом перевод:** перед переводом модель кратко описывает
  ситуацию по контексту — кто к кому обращается, что уже произошло и что
  делает эта реплика. Адресат, род и отрицания берутся из понимания сцены,
  а не наугад.
- **Гендер:** пол берётся из карты `casts/gender.mts` по имени спикера —
  это единственный источник истины (теги пола удалены из POT/po
  2026-11-03 — вводили в заблуждение). Как применять пол — правило 4;
  пол Narrator в карте — это голос озвучки, а не грамматика строки.
- **Без тона:** тона (`#. emotion:`) — только для озвучки, в po его нет.
  Качество перевода: микро-правила ниже → механическое ревью
  (`translate_review`, 11+ классов, режим `--all` для легаси без фильтра HEAD)
  → **судья LLM** (`translate_judge`, промпт v10: rubric «смысл/грамматика/
  род»; калибровка E2E на 64 дефектах + фразах-ложняках 2026-11-06 —
  61/64 при 0 ложных на чистых). Судья только предлагает флаги —
  подтверждает и чинит агент. Ремонт подтверждённых строк: раннер
  `translate_run --retrans <файл индексов>` (гейты + судья на каждой).
- **Протокол ответа:** JSON вида
  `{"scene":"<краткая заметка о ситуации>","tr":"<перевод>"}` — поле `scene`
  заставляет модель сначала понять сцену и уходит в лог ревью.
- **Файлы:** формирование `template.pot` / `po` — скилл `renpy-po`
  (`potgen`, `po:update`, `po:check`, `po_list`, `po_fix`). Здесь — только
  сам перевод.
- **Канон имён:** принятые написания — в строках po с
  `msgctxt "speaker-name"`; перевод им следует для однообразия (сами эти
  строки не переводятся — их `msgstr` и есть канон).

## МИКРО-ПРАВИЛА (для промпта; владелец ревьюит)

<!-- ПРАВИЛА -->

1. Пиши так, будто эта строка изначально написана на языке перевода:
   читатель не должен чувствовать перевод.
2. Сохраняй смысл и художественный замысел автора — что именно сказано и как
   это звучит (ирония, нежность, грубость, сарказм). Дословность замыслу
   не помогает: переводи замысел, а не слова. Не смещай значения и не
   усиливай/не смягчай эмоциональный вес: переводи ровно то, что сказано.
3. Эротическая проза 18+: пиши откровенно и по делу, желательно без медицинщины и без
   приличных заглушек — регистр такой, каким задана сцена. Главное передать
   художественный смысл авторского перевода 18+.
4. Гендер: согласование идёт по полу подлежащего. «Я…» — по говорящему;
   в наррации — по персонажу, о ком идёт речь; обращение во втором лице
   прошедшего времени (ты пришёл / ты пришла) — по полу того, К КОМУ
   обращаются: адресат виден из соседних реплик, а не из пола говорящего.
   Сомневаешься в поле персонажа — сверяйся с картой `casts/gender.mts`:
   там описаны все персонажи, спор решает она, а не интуиция.
   Никаких скобочных форм рода — «прав(а)», «видел(а)»: выбери род
   однозначно и пиши без скобок.
5. Длина свободна: фраза может быть и короче, и длиннее оригинала — если так
   раскрывается её художественный замысел (одно английское слово спокойно
   становится тремя русскими, и наоборот).
6. Имена персонажей остаются именами: пиши их в каноническом написании
   из строк speaker-name файла po, не переводи и не переписывай.
   Название игры (The Survival of Sarah Rose, TSSR) тоже остаётся как есть.
   Названия мест и короткие метки (Castle Reinmeer, пункты выбора) — только
   меткой или названием, никогда не разворачивай их в предложение.
   Степень обращения — по отношениям: близкие и равные — «ты»; официальные
   встречи, переговоры, чужие, властные — «вы». Внутри одной сцены —
   последователен. Титулы — в принятой в языке форме.
7. Служебные части строки (плейсхолдеры %s, {name}, разметка {i}...{/i},
   [config...]) проходят в перевод без изменений — и ничего лишнего не
   добавляй: ни имени спикера, ни лейбла, ни переносов строк, которых
   нет в оригинале. Контекст соседних строк — только для понимания:
   в переводе ровно эта строка, никогда не переноси в неё текст соседних
   (баг: в перевод строки попадала реплика соседа).

## Рецепт промпта (проверен на Index-Translate-9B; переносится на другие модели)

Системный: «You translate this game into <язык>. Follow these rules:» + блок
МИКРО-ПРАВИЛ целиком. Пользовательский, по порядку:

1. `CONTEXT — for understanding only; translate ONLY the target line:` —
   `PREVIOUS lines (already happened):` (3 строки ДО) и `NEXT line (comes right
AFTER this line):` (1 строка ПОСЛЕ), EN с msgctxt.
2. `NAMES — exact renderings; the GENDER in parentheses drives grammatical
agreement (trust it, never guess from the name):` — пары
   `Имя -> канон (MALE — он/-лся/-л | FEMALE — она/-лась/-ла)` из speaker-name
   и канонов мест; без канона — не выдумывать.
3. `Said by: <спикер> (gender …)` / `EN: <строка>`; для меню/UI — пометка
   «MENU/UI LABEL — keep it a short action label».
4. STEP 1 — RESEARCH: 2–3 фразы **по-английски (Latin script only)**: кто к кому
   обращается, что уже произошло, что делает строка + пол каждого персонажа из NAMES.
5. STEP 2 — TRANSLATE ONLY: tr — только перевод; сохранить каждую фразу
   оригинала, грамматически верно, ничего лишнего.
6. Самопроверка:2-е лицо прошлого = адресат из ресёрча; согласование = род из
   NAMES; имена точно как в NAMES; не продолжать историю дальше строки.
7. `Output ONLY JSON {"scene":"…","tr":"…"}.` — **temperature 0**; при срабатывании
   гейта повтор с temp 0.7, затем 1.0 (при temp0 брак детерминирован).

## QA-чеклист (до применения перевода)

Механически: утечка/склейка с соседней строкой (tr ≈ перевод соседа при разных
оригиналах) и **вклейка ЧАСТИ соседа** (общий словесный фрагмент ≥3 слов и
≥2 содержательных при разных EN-соседях — второй тип ловит вплетённое второе
предложение); **модель при temp0 детерминированно может перевести СОСЕДНЮЮ
строку целиком или продолжить её** (проверено E2E 2026-11-06 — гейт ловит,
повтор 0.7/1.0 разбивает детерминизм); искажения имён (Левенштейн ≤2 к канону;
склонения — не брак); женский род при мужском имени; потеря отрицания
(EN not/no/never…, а в tr нет «не/нет/ни…/без»); смена регистра ты/вы;
скобочные формы рода (прав(а)); потерянная и чужая разметка; сломанные
экранирования; название игры и канон мест; метка, разёрнутая в предложение;
вклепанная реплика в короткую наррацию («…: «…»» после атрибуции ≤5 слов).

Семантически: судья v10 (`translate_judge <lang> <n> [--file <индексы>]
[--spread]`) — ловит «не ту строку», выдуманный смысл и потерю информации;
чистые фразы-ложняки (род по адресату, идиомы, кривой источник) — известный
потолок модели: флаги по ним отклоняются глазами, хардкод-списков нет
(правило владельца: тюнинг промпта, не индексы).

Процесс: dry-прогон (ничего не записывается) → разбор предложений (ремонт
старого — режим keep) → применение только лучшего → повторный аудит = 0 → po:check.
Полная сплошная проверка корпуса: судья по всему po (~8 ч на 69k строк при
0.4 с/стр) + `translate_review --all`.
