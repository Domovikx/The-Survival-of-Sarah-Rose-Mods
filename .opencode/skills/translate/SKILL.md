# translate — построчный перевод (с нуля)

## Как устроен перевод

- **Построчно:** одна строка = один перевод. Переводится только целевая строка.
- **Контекст:** перед строкой модели даются **3 реплики ДО** и **1 ПОСЛЕ**
  (если они есть) — они нужны, чтобы понять ситуацию, а не для перевода.
- **Сначала ресёрч, потом перевод:** перед переводом модель кратко описывает
  ситуацию по контексту — кто к кому обращается, что уже произошло и что
  делает эта реплика. Адресат, род и отрицания берутся из понимания сцены,
  а не наугад.
- **Гендер:** пол берётся из карты `casts/gender.mts` по имени спикера —
  это единственный источник истины (теги пола удалены из POT/po
  2026-11-03 — вводили в заблуждение). Как применять пол — правило 4;
  пол Narrator в карте — это голос озвучки, а не грамматика строки.
- **Без тона:** тона (`#. emotion:`) — только для озвучки, в po его нет.
  Качество перевода: микро-правила ниже → механическое ревью
  (`translate_review`, 11+ классов, режим `--all` для легаси без фильтра HEAD)
  → **судья LLM** (`translate_judge`, промпт v10: rubric «смысл/грамматика/
  род»; калибровка E2E на 64 дефектах + фразах-ложняках 2026-11-06 —
  61/64 при 0 ложных на чистых). Судья только предлагает флаги —
  подтверждает и чинит агент. Ремонт подтверждённых строк: раннер
  `translate_run --retrans <файл индексов>` (гейты + судья на каждой).
- **Протокол ответа:** JSON вида
  `{"scene":"<краткая заметка о ситуации>","tr":"<перевод>"}` — поле `scene`
  заставляет модель сначала понять сцену и уходит в лог ревью.
- **Файлы:** формирование `template.pot` / `po` — скилл `renpy-po`
  (`potgen`, `po:update`, `po:check`, `po_list`, `po_fix`). Здесь — только
  сам перевод.
- **Канон имён:** принятые написания — в строках po с
  `msgctxt "speaker-name"`; перевод им следует для однообразия (сами эти
  строки не переводятся — их `msgstr` и есть канон).

## Рецепт промпта (проверен на Index-Translate-9B; переносится на другие модели)

Системный: «You translate this game into <язык>. Follow these rules:» + блок
МИКРО-ПРАВИЛ целиком. Пользовательский, по порядку:

1. `CONTEXT — for understanding only; translate ONLY the target line:` —
   `PREVIOUS lines (already happened):` (3 строки ДО) и `NEXT line (comes right
AFTER this line):` (1 строка ПОСЛЕ), EN с msgctxt.
2. `NAMES — exact renderings; the GENDER in parentheses drives grammatical
agreement (trust it, never guess from the name):` — пары
   `Имя -> канон (MALE — он/-лся/-л | FEMALE — она/-лась/-ла)` из speaker-name
   и канонов мест; без канона — не выдумывать.
3. `Said by: <спикер> (gender …)` / `EN: <строка>`; для меню/UI — пометка
   «MENU/UI LABEL — keep it a short action label».
4. STEP 1 — RESEARCH: 2–3 фразы **по-английски (Latin script only)**: кто к кому
   обращается, что уже произошло, что делает строка + пол каждого персонажа из NAMES.
5. STEP 2 — TRANSLATE ONLY: tr — только перевод; сохранить каждую фразу
   оригинала, грамматически верно, ничего лишнего.
6. Самопроверка:2-е лицо прошлого = адресат из ресёрча; согласование = род из
   NAMES; имена точно как в NAMES; не продолжать историю дальше строки.
7. `Output ONLY JSON {"scene":"…","tr":"…"}.` — **temperature 0**; при срабатывании
   гейта повтор с temp 0.7, затем 1.0 (при temp0 брак детерминирован).

### Регистр 18+ в готовом переводе (`tone_fix.mts`)

Правка уже переведённого корпуса, когда медицинский или книжный регистр
проскочил в `po/<lang>.po`. Не переперевод: строку лечит модель, код лишь
вклеивает её ответ и проверяет, что строка не сломалась.

```bash
node .opencode/skills/translate/tone_fix.mts --lang ru                     # dry-run, отчёт в tmp/
node .opencode/skills/translate/tone_fix.mts --lang ru --only 1015,1988    # конкретные записи
node .opencode/skills/translate/tone_fix.mts --lang ru --repeat 3          # E2E: разброс по повторам
node .opencode/skills/translate/tone_fix.mts --lang ru --apply             # записать принятое в po
```

Как это работает (`tone_lexicon.mts` — детерминированная часть, 14 тестов):
детектор по лексиконам 10 языков находит строки-кандидаты (без модели —
дёшево и воспроизводимо), дальше модель получает EN-оригинал, текущий
перевод и **точное вхождение** термина и возвращает только
`{fragment, replacement}`. Вклейку делает код, поэтому остальная строка
физически не может пострадать; механические гейты бракуют правку с остатком
клиники, потерянным именем, сломанными тегами, латиницей или сменой финальной
пунктуации, а судья LLM проверяет смысл, согласование хвоста и регистр.
Брак возвращается модели с замечанием (до 4 попыток), непринятое остаётся
как было и попадает в `tmp/tone_<lang>.json` (`proposals` — что предлагалось
и почему отклонено) для вычитки человеком.

Лексикон **только подсвечивает** кандидатов: готового текста замены в нём нет
и быть не должно — формулировку каждый раз пишет модель (правило владельца
2026-11-13: «перевод копипастом делать нельзя, это творческий процесс»).

Перед прогоном по языку снимаем **словарь книги** — `tone_census.mts --lang <l>`
показывает, какими словами корпус уже переводит pussy/cock/cunt/ass (ищет
лексику, характерную именно для этих строк, а не «и/в/её»). Найденное уходит
в `REGISTER_HINT` языка: правка обязана попадать в сложившийся словарь, а не
придумывать свой. Так и нашлось, что `her sex` в 30 из 84 строк переведено
как «половые органы», при том что для pussy/cunt книга говорит «киска».

## Правка родным форматом переводчика (`tone_native.mts`)

Главный инструмент правки регистра по итогам замера 2026-11-13. `tone_fix`
зовёт модель как «редактора с JSON», а Index-Translate обучена одному формату:
один user-message без system, `temperature=0`, `chat_template_kwargs.
enable_thinking=false`, ответ — только текст (карточка модели; JSON-редактирование
давало «твоё киска», «киска горят» и резинового судью-одноклассника).

```bash
node .opencode/skills/translate/tone_native.mts --lang ru                  # только дефектные строки, dry-run
node .opencode/skills/translate/tone_native.mts --lang ru --only 1015,1988
node .opencode/skills/translate/tone_native.mts --lang ru --only-file tmp/idx.txt --apply
```

Что важно знать по опыту:

- **Скорость** 0.3–0.4 с/строка (9B) против ~10–13 с у 35B: язык целиком — минуты.
- Перед переводом код добавляет **жёсткие ограничения** её родного промпта:
  глоссарий имён (`buildNameCanon` + `nameGlossary`, иначе «Belmont» →
  «Белмонт»), пол персонажей (`charsOf`, иначе «протёрла»), словарь книги.
  Запрет клиники берётся из лексикона (`banTerms`) — **не пишем его руками**,
  иначе расходится с детектором.
- Запрет в промпте — не гарантия: если слово есть в оригинале («to
  masturbate»), модель может его вставить. `translateClean` делает один
  переспрос с прямым указанием на утечку; ищет утечку **детектором**
  (`findTerms`), а не именами из списка — в тексте слово стоит в падеже.
- **Проверка — обратный перевод** (RU→EN) и F1 с оригиналом: это снова её
  обученная задача, в отличие от «оцени свою правку». F1 0.5–0.9 —
  диагностика, не приговор: смысл всё равно смотрит человек.
- Слабые термины (влагалище, эрекция, промежность, мастурбация, анус, клитор, матка, лобок) —
  `weak` в лексиконе: сами по себе не дефект и в запрет не попадают, правим
  только за компанию с настоящей канцелярщиной (решение владельца 2026-11-13).

### Гочи `tone_native` (пойманы 2026-11-13)

- **`--only` без значения = `[0]`** (`Number("") === 0`), инструмент молча
  переводил заголовок игры. Починено: пустые элементы отсеиваются. Заголовок
  («The Survival of Sarah Rose…») — это `idx 0`, его правка не нужна никогда.
- **Словарь книги (`STYLE`) нужен на КАЖДЫЙ язык.** Без него модель уходит в
  эвфемизмы: `zh` давал «下体» вместо «小穴», `ja` — «性器»; `banTerms` сам по
  себе только запрещает, но не говорит, чем заменить. Списки — в `STYLE`
  (`tone_native.mts`).
- **Ложные срабатывания детектора** (исправлены, покрыты тестами): `zh` «逼» —
  обычный глагол «вынуждать» (逼问/逼迫), «下身» — «низ тела» и часть
  «俯下身»; `pl` «chuj» ловился внутри «wdmuchuje»; `ko` «보지» — ещё и форма
  глагола «видеть» («보지 않으려는»). Границы слова и узкие шаблоны обязательны.
- **Книжное слово — не огрубление.** `es` coño, `it` figa/fica, `pt` buceta
  переводили «pussy»/«her sex», как и русское «киска»; из `VULGAR` сняты.
  `de` Masturbieren / `自慰` / `자위` — точный эквивалент меню EN «Masturbate»,
  поэтому `weak`, а не запрет.
- **Механические гейты не ловят подмену смысла.** «blew an old sailor» →
  «scopai / fodi» (трахнула вместо минет) прошло с F1 0.67. Вывод модели
  читается глазами; `--note` с прямым объяснением смысла обычно чинит.
- **Судья на не-`ru` путает слова-омографы.** На полном аудите 9 демо-языков
  (2026-11-13) он дал 2 ложных флага на итальянском: «Sarah **ride**» (ridere,
  «смеётся») и «Kate **rise**» (прошедшее) принял за непереведённый английский.
  При разборе флагов не-`ru` это первое, что надо проверять: слово может быть
  своим. Обратная сторона: 0–3 флага на 1806 строк — ещё не «хорошее качество»,
  судья тот же Index-Translate-9B и калиброван на `ru`.
- **`msgstr = msgid` — не автоматически дефект.** Механическая сверка 9 языков
  дала 56–76 таких строк на язык, но это имена спикеров, UI-токены (`Auto`,
  `Tab`, `Page Up`), короткие реплики («Kate!», «Ooh.»). Смотреть, а не считать.
- **Правка одной строки может испортить соседнее.** Перегенерация по `--note`
  на 205 якорях `ru` (2026-11-13) дала 4 регрессии: «трётся» → «теря»,
  «задница» → «киска», «жена/ей» → «Дворянка/ему», «Запястья» → «Задние
  запястья». `--note` сужает, но не гарантирует: результат вычитывается.
- **Чистую грамматику модель часто «не меняет»** (отвечает тем же текстом,
  гейт «правка ничего не изменила»). Согласование/падеж надёжнее ставить
  точечно `po_fix --set 'idx=текст'` — это разрешённый ручной ремонт
  найденного аудитом ляпа, а не перевод.
- **Новый CJK-символ в переводе = перегенерация шрифтов.** Сабсеты
  (`fonts/NotoSansCJK*.otf`) режутся по символам всех `po/`+`tl/`; если перевод
  добавил символ, `font_guard` падает. Чинить `subset_fonts.mts` из **полных**
  Noto (в git — в HEAD), на сабсете прогон запрещён.

## QA-чеклист (до применения перевода)

Механически: утечка/склейка с соседней строкой (tr ≈ перевод соседа при разных
оригиналах) и **вклейка ЧАСТИ соседа** (общий словесный фрагмент ≥3 слов и
≥2 содержательных при разных EN-соседях — второй тип ловит вплетённое второе
предложение); **модель при temp0 детерминированно может перевести СОСЕДНЮЮ
строку целиком или продолжить её** (проверено E2E 2026-11-06 — гейт ловит,
повтор 0.7/1.0 разбивает детерминизм); искажения имён (Левенштейн ≤2 к канону;
склонения — не брак); женский род при мужском имени; потеря отрицания
(EN not/no/never…, а в tr нет «не/нет/ни…/без»); смена регистра ты/вы;
скобочные формы рода (прав(а)); потерянная и чужая разметка; сломанные
экранирования; название игры и канон мест; метка, разёрнутая в предложение;
вклепанная реплика в короткую наррацию («…: «…»» после атрибуции ≤5 слов).

Семантически: судья v10 (`translate_judge <lang> <n> [--file <индексы>]
[--spread]`) — ловит «не ту строку», выдуманный смысл и потерю информации;
чистые фразы-ложняки (род по адресату, идиомы, кривой источник) — известный
потолок модели: флаги по ним отклоняются глазами, хардкод-списков нет
(правило владельца: тюнинг промпта, не индексы).

Процесс: dry-прогон (ничего не записывается) → разбор предложений (ремонт
старого — режим keep) → применение только лучшего → повторный аудит = 0 → po:check.
Полная сплошная проверка корпуса: судья по всему po (~8 ч на 69k строк при
0.4 с/стр) + `translate_review --all`.
