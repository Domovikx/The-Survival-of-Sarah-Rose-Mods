# skill-review-rpy

Проверяю качество перевода одного .rpy файла, исправляю найденные проблемы и перепроверяю.

## Процесс

1. **Проверка** — проанализируй файл по критериям ниже, составь список проблем
2. **Исправление** — если найдены проблемы (ISSUES), отредактируй файл: исправь каждую проблему в `new` строках
3. **Перепроверка** — повторно прогони проверку исправленного файла
4. **Цикл** — повторяй шаги 2-3 пока все проблемы не будут устранены (не более 3 итераций)
5. **Финал** — верни итоговый отчёт

## Формат ответа (машиночитаемый)

Отчёт должен быть в строгом формате, чтобы skill-translate-rpy мог распарсить проблемы и исправить их.

### Если всё хорошо (с первой проверки или после исправлений)

```text
APPROVED
```

### Если есть проблемы — исправь и перепроверь

1. Для каждой проблемы из списка отредактируй соответствующую `new` строку в файле
2. После исправления всех проблем — повторно прогони проверку
3. Если после исправлений появились новые проблемы — исправь их (макс 3 итерации)

### Формат финального отчёта

```text
APPROVED
```

Или если после 3 итераций проблемы остались:

```text
ISSUES_REMAINING
- line:42 | type:гендер | old:"you saw" | new:"ты видел" → не удалось исправить
```

### Промежуточный формат проблем (для исправления)

```text
ISSUES
- line:42 | type:гендер | old:"you saw" | new:"ты видел" → женский род (адресат — Сара)
- line:87 | type:мат | old:"fucking" | new:"ёбаный" → заменить на "грёбаный/чертов"
- line:155 | type:калька | new:"обслужила его ртом" → неестественно, рекомендуется поискать лучшую замену например "сделала минет"
```

### Типы проблем (type)

| type               | Что проверяет                                      |
| ------------------ | -------------------------------------------------- |
| `гендер`           | Согласование рода глаголов при `ты`, `я`, `она/он` |
| `ты/вы`            | Смена регистра обращения внутри файла              |
| `калька`           | Англо-русская калька, неестественное звучание      |
| `термин`           | Несовпадение перевода одинаковых old внутри файла  |
| `бюрократизм`      | Стоп-слова (является, осуществляет и т.д.)         |
| `междометие`       | Английское междометие не заменено на русское       |
| `типографика`      | Кавычки, тире, пробелы                             |
| `потеря`           | Потеря деталей/смысла в переводе                   |
| `абсурд`           | Физически невозможное описание                     |
| `английское_слово` | Латинские буквы в new (кроме имён)                 |
| `пустая_строка`    | new "" пустая                                      |

Каждая проблема содержит номер строки, тип, и конкретное описание что не так и как исправить.  
Формат должен быть строго одной строкой на проблему.

## Критерии проверки

### 1. old-строки не повреждены

Сравни `old` строки с оригиналом (git HEAD). Если `old` изменился — это критическая ошибка.

**Проверка:**

```bash
git diff HEAD -- <путь_к_файлу>
```

Если в diff есть изменения в строках, начинающихся с `old "` — файл повреждён.

### 2. Все строки переведены

Нет строк, где `new` совпадает с `old`.

### 3. Нет английских слов в new

`new` не должен содержать латинских слов, кроме:

- Имён собственных персонажей (Sarah, Rose, King, Orwell и т.д.)
- Спецтерминов (Ren'Py, Steam, PC, OK)
- Единиц измерения (kg, km, %)

### 4. Синтаксис Ren'Py

- Каждый `translate ru strings:` блок имеет правильные отступы (4 пробела)
- Пары old/new идут последовательно
- Нет пустых `new ""` строк
- Нет дублирующихся блоков `translate ru strings:` внутри файла

### 5. Согласование

- Глаголы при `ты` согласованы по роду с адресатом
- Нет ошибок падежа, числа, рода
- Фразы звучат естественно по-русски

### 5.5. Единообразие обращений (ты / Вы)

Проверь, что тон обращения между персонажами не ломается внутри файла:

- Если персонаж А обращается к Б на «ты» — он должен делать так ВО ВСЕХ репликах.
- Исключение: сюжетно обоснованная смена (ссора → официоз, романтическое сближение).
- Обращение к монарху/лорду — традиционно на «Вы».
- **В эротических сценах:** переход с «Вы» на «ты» — маркер сближения. Если в интимной сцене персонажи вдруг переходят на «Вы» — это выглядит неестественно. Проверь, что регистр обращения выдержан на протяжении всей интимной сцены.

### 5.6. Гендерное согласование (род говорящего и адресата)

В английском языке глаголы прошедшего времени и прилагательные не имеют категории рода. В русском языке род субъекта критически важен. Ошибки согласования рода говорящего или адресата разрушают логику сцены.

**Алгоритм проверки:**

1. Определи пол говорящего по контексту (тег персонажа, местоимения в окружении, обращения)
2. Определи пол адресата (если в реплике «ты» + глагол прошедшего времени)
3. Если контекста недостаточно — обратись к оригинальному английскому скрипту (ищи `he/she`, `his/her`, `bro`, `man`, `girl`, `sir`, `ma'am`)
4. Отметь несоответствия:
   - Глагол прошедшего времени не совпадает по роду с говорящим (девушка: «Я пошёл»)
   - Глагол при «ты» не совпадает по роду с адресатом (к девушке: «Ты видел?»)
   - Ошибки в 3-м лице (местоимение + глагол: «Она пришёл»)
   - Мужской род по умолчанию в нарративе, если фокальный персонаж — женщина
5. Если род невозможно определить — текст должен быть переформулирован без родовой зависимости (не «Я видел», а «Мне довелось увидеть»)

**6. Дополнительная проверка нейтрализации:** Если в файле встречаются строки, где род так и не удалось определить по контексту, а в переводе стоит мужской род «по умолчанию» — отметь это как ошибку. Проверь, какие приёмы нейтрализации могли бы сработать (настоящее время, безличная конструкция, пассив, существительное вместо глагола — полный список в skill-translate-rpy раздел 1.1). Пример:

- [строка 55] Род по умолчанию: «я не был готов» — говорящий не идентифицирован ни по контексту, ни по оригиналу. Нужна нейтральная конструкция: «я оказался не готов» или переформулировать в настоящее время.

### 6. Полнота перевода

Проверь, что переведены **все** блоки в файле — от первого `translate ru strings:` до последнего.

### 7. Русская типографика

Проверь пунктуацию в `new` строках:

- **Кавычки**: должны быть «ёлочки», а не прямые "лапки". Лапки допускаются только внутри «ёлочек» для вложенных кавычек.
- **Тире**: длинное тире (—) с пробелами с обеих сторон. Дефис (-) — только внутри слов. Короткое тире (–) — для диапазонов чисел.
- **Многоточие**: ровно три точки `...`, в конце предложения четвёртой точкой становится точка предложения (`....`).
- **Пробелы**: нет двойных пробелов, пробел перед длинным тире и после.

### 8. Стилистическая естественность (кальки)

Проверь `new` на типичные англо-русские кальки:

- **Пассивный залог**: `было сделано` → звучит неестественно
- **Причастные обороты**: длинные предложения с `which`/`that` лучше разбить
- **Порядок слов**: русский порядок слов свободный — не должен копировать английский SVO
- **Буквальные идиомы**: `it's raining cats and dogs` → не «дождь из кошек и собак»
- **Канцеляризмы**: `осуществлять`, `является`, `представлять собой` — в диалогах неестественно

### 8.5. Стоп-слова (бюрократизмы)

Проверь `new` на наличие слов-паразитов русского официоза: является, осуществлять, представлять собой, в рамках, в целом, по факту, с целью, вышеуказанный, соответствующий, имеет место быть, в свою очередь, со стороны, в зависимости от.

### 9. Адаптация междометий и звуков

Проверь, что английские междометия заменены на русские аналоги:

- `Uh... / Umm...` → `Эм... / М-м...`
- `Ah! / Oh!` → `А! / О! / Ах!`
- `Hmm...` → `Хм...`
- `Ugh... / Urgh...` → `Тьфу... / Фу... / Угх...`
- `Wow! / Whoa!` → `Ничего себе! / Ого!`
- `Hey!` → `Эй! / Ай!`
- `Gah! / Argh!` → `Ай! / Чёрт! / Проклятье!`
- `_sigh_ / _sighs_` → `_вздыхает_`
- `_laugh_ / _chuckle_ / _giggle_` → `_смеётся_ / _хихикает_ / _усмехается_`
- `_cough_ / _clears throat_` → `_кашляет_ / _прочищает горло_`
- `_gasp_` → `_ахает_ / _затаивает дыхание_`
- `_groan_ / _moan_` → `_стонет_`
- `_whimper_` → `_хнычет_`
- `_pant_ / _pants_` → `_тяжело дышит_`

### 10. Длина строк (fit-проверка)

Русский текст в среднем на 15–30% длиннее английского. Если длина `new` более чем в 2 раза превышает длину `old` — отметь строку как потенциально проблемную (может не поместиться в диалоговое окно).

### 11. Числа прописью

В русской художественной литературе числа от 1 до 10 принято писать словами. Исключение: даты, игровые механики, меры, статистика, цены.

### 12. Консистентность терминов (глоссарий)

Один и тот же английский термин должен переводиться одинаково во всех строках файла. Найди повторяющиеся `old` и сравни их `new`. Если одинаковый `old` переведён по-разному — отметь нарушение. Имена персонажей, титулы (`King`, `Queen`, `Lord`), названия локаций, рас, магических терминов должны быть единообразны.

**Проверка глоссария:** Если в проекте есть глоссарий — сверь ключевые термины файла с ним. Если нет — проверь консистентность хотя бы внутри проверяемого файла. Особенно критично для 18+ лексики: `cock`/`cunt`/`thrust` должны переводиться одинаково во всех эротических сценах файла (если контекст не требует иного).

### 13. Проверка уровней лексики на чрезмерный (мат / грубость)

### 13.1. Клинические термины в 18+ сценах

Проверь, что в эротических сценах нет переизбытка медицинских/клинических терминов.

### 14. Специфика 18+ контента (общая)

В эротических сценах проверь:

- **Степень откровенности** соответствует оригиналу (не вульгарнее и не целомудреннее)
- **Эвфемизмы**: английские метафоры заменены русскими аналогами, а не транслитом/кальками
- **Повторяющиеся термины** единообразны во всех интимных сценах (см. глоссарий в п. 12)
- **Нецензурная лексика**: проверка по п. 13
- **Согласование рода** в интимных сценах (глаголы при `ты`)
- **Ты/Вы регистр** в эротических сценах выдержан (см. п. 5.5)

### 15. Словарное разнообразие в 18+ сценах

Проверь, что в эротических сценах нет избыточного повторения одних и тех же терминов для частей тела и действий. Если на 3+ страницы текста используется только `член` и `киска` — это признак бедного словаря.

**Признаки проблемы:**

- Один и тот же термин для половых органов повторяется в каждой строке подряд
- Нет синонимической замены: всегда только `член`, никогда `ствол`/`плоть`/`жезл`
- Отсутствуют образные описания (нет метафор, сравнений, чувственных эпитетов)
- Действия сводятся к 1-2 глаголам (`вошёл`, `толкнулся`)

**Если словарь беден — отметь строки и предложи добавить вариативности, но не указывай конкретные замены (это задача переводчика).**

### 16. Смысловая целостность (anti-bullshit check)

Проверь, что перевод не содержит нелепых/невозможных описаний и не теряет детали оригинала.

#### 16.1. Нелепые описания (абсурд)

Прочитай `new` строки **без сверки с `old`** — на естественность русского языка. Если фраза звучит физически невозможной или нелепой — скорее всего, переводчик перепутал части тела или действия:

- ❌ `"Усик раздвинул ей челюсть"` — челюсть не раздвигается
- ❌ `"Она вошла в него коленями"` — если в сцене не описана акробатика, это ошибка

**Признаки:**

- Сочетание глагола и объекта звучит неестественно для носителя (`раздвинуть челюсть`, `войти коленями`)
- Части тела не соответствуют сцене (челюсть вместо бёдер, локоть вместо колена)

Если нашёл такую строку — отметь и сошлись на контекст сцены.

#### 16.2. Потеря деталей (обобщение)

Сравни количество значащих элементов в `old` и `new`. Если в `new` заметно меньше конкретики — отметь как потерю смысла:

- `old: "She pulled the rod from between Sarah's legs."`
- `new: "Она вытащила стержень из неё."`
- ⚠️ Потеряна локация `from between Sarah's legs` → заменено на размытое `из неё`

**Что должно быть проверено:**

- Локации (`from between`, `under`, `behind`, `near` → не «рядом», а конкретно)
- Принадлежность (`Sarah's`, `his`, `her` → не «её», а чья именно)
- Образ действия (`slowly`, `gently`, `suddenly`, `carefully` — не выброшены)
- Сравнения (`like`, `as if`, `as though` — не пропущены)

#### 16.3. Тест обратного перевода (back-translation check)

Если строка подозрительна — мысленно переведи `new` обратно на английский. Сравни с `old`.

- `new` → back: `"She pulled the rod out of her."`
- `old`: `"She pulled the rod from between Sarah's legs."`
- ❌ Несоответствие: потеряна локация `from between`

Если `new` при обратном переводе заметно короче/беднее `old` — отметь как смысловую потерю.
