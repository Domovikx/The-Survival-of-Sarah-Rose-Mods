«незакрытым UI-ветка (выдуманная эмоция для кнопок можно записать отдельной задачей,
приоритет средний, вначале углубленный ресерч и подтреврждение бага или отрицание бага,

«посмотри пожалуйста есть ли элементы меню для для переводов, возможно они в сырье

## Цель

Когда в каталоге есть записи без спикера (`ui`, `menu`, `speaker-name`), я хочу, чтобы построчный
переводчик относился к ним как к интерфейсу (без эмоции диктора, без эрогенных авточеков и судьи),
чтобы короткие UI-строки вроде «Save» не отклонялись авточеком длины, а перевод шёл своим контекстом.
Критерий «стало лучше»: доля rejected среди `ui/menu/speaker-name` падает с ~30% до <5%, при этом
поведение озвучки (`voice_batch`) и содержимое POT/ru.po не меняются вообще.

## Контекст (что есть сейчас)

Проверено 2026-10-24:

- **UI/menu УЖЕ в POT** — гипотеза «может их там нет» не подтвердилась. Префиксы msgctxt в
  `po/template.pot`: `speaker` 68 357, `menu` 525, `speaker-name` 152, `ui` 86. Константы —
  `renpy-po/potgen.mts:102-104` (`CTX_MENU`, `CTX_UI`, `CTX_SPEAKER_NAME`).
- **Озвучка уже правильно их пропускает.** `voice_batch.mts:92-100` — категория по msgctxt
  (`speaker:*` → dialogue/narration, `menu` → menu, всё прочее → ui), `voice_batch.mts:229` —
  озвучиваются только `dialogue`/`narration`, остальные `continue`. То есть задуманное владельцем
  «спикер → озвучить, остальное → просто перевод» УЖЕ работает, чинить нечего.
- **Покрытие реального текста screens.rpy полное.** В `game/screens.rpy` 97 активных `_()`-строк
  (UI-файлы `art/gui/options/new_gallery/replay_gallery/prosalaric` дают 0–2 шт). Реально
  показываемого текста 73; «непокрытых 7» оказалось ложью сравнения: 4 — экранирование `\n`
  (`Left Trigger\nLeft Shoulder` в POT есть как `\\n`), 3 — **мёртвый закомментированный код**:
  `#textbutton _("Start")` (`screens.rpy:331,425`), `_("Main Menu")` (`:362,452`), `_("Quit")`
  (`:376,466`).
- **`script.rpy` (5.7 MB) прямых UI-литералов не несёт**: 0 вызовов `_()`, 150 блоков `menu` —
  они и дают `msgctxt "menu"` в POT через potgen.
- **ru.po уже готов**: `ui` 86/86 (100%), `menu` 494/525 (94%), `speaker-name` 152/152 (100%).
- **НАЙДЕН БАГ: UI-записи идут через тот же пайплайн, что и эрогенный диалог.**
  - Очередь перевода — все пустые записи без фильтра по категории
    (`po_translate.mts:441-450`).
  - `userPrompt` подставляет выдуманную эмоцию: `emotion ?? "Curiously observing"`
    (`po_translate.mts:191`) — для «Save» это бессмысленно; строка `speaker: ui` (`:195`) тоже
    некорректна для интерфейса.
  - Авточек длины `ratio 0.5–1.6` (`po_translate.mts:218-219`) режет короткий перевод:
    локальный прогон `checkTranslation` даёт **REJECT** на `Save → Guardar` (×1.75) и
    `Mute All → Silenciar todo` (×1.75), при этом `Back → Atrás`, `Skip → Omitir` проходят.
  - Судья (`po_translate.mts:231-235`) оценивает `ui/menu`-строки по правилам
    «frank erotic prose / NO clinical terms» — неприменимо к «Fullscreen».
  - Факт из `tmp/po_translate_es.jsonl` (выборка, 2026-10-24): `menu` ok 153 / rejected 8;
    `ui` ok 20 / rejected 11; **`speaker-name` ok 34 / rejected 60** — худший фронт.
    Причина «длина» среди отклонённых ui/menu — 16 записей (`After Choices`, `Fullscreen`,
    `Hide UI`, `Ask Kate`, `Camp Soldier`, `Hide`...).
  - Пустых в es.po сейчас: `menu` 371, `speaker-name` 119, `ui` 65.
- **msgctxt уже несёт личный признак** — трёх указанных в цитате префиксов (`ui`/`menu`/

## Журнал решения (2026-10-24)

**Крит-фикс (по указанию владельца): проверка длины ВЫПИЛЕНА полностью** — «для n языков это
критический баг, в китайском 1 иероглиф на слово». Что вырезано:

- `po_translate.mts` — авточек `ratio` из `checkTranslation` (был `lenMin–lenMax`);
  критерий `length (subtitles)` в промпте судьи заменён на явный запрет штрафовать длину.
- `po_langs.mts` — поля `lenMin`/`lenMax` удалены из интерфейса и всех 10 профилей;
  правило COMMON «Length within the allowed range» заменено на «NO length requirement»;
  ratio-числа (0.3x–2.5x) в правилах ja/ko/zh переписаны без цифр («shorter is natural»).
- `po_translate.test.mts` — тесты перевёрнуты в гарды: длина НЕ проверяется (и полей в
  профилях нет), иначе тест упадёт при регрессии.
- `skill-translate-es-po/SKILL.md` — «длина ±диапазон» и «±30%» из авточеков/стиля убраны.
- Проверки: oxlint/prettier/typecheck чистые, тесты 14/14, вся матрица 328/328.
- Живая валидация: перевод перезапущен чистым стопом на новом коде; 45 записей после
  рестарта → 0 отклонений «за длину» (jsonl, сравнение с доковской границей 22 804).

Остаётся в рамках задачи (НЕ сделано): UI-ветка prompt (эмоция «Curiously observing» и
`speaker: ui` для интерфейса), применение эрогенного судьи к UI/menu, разбор 60/94 rejected
у `speaker-name`.
