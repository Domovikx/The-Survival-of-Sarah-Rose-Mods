## Предварительный ресёрч (4 саб-агента + локальные замеры, 2026-10-12/13)

### Де-факто 2026 (для VN/игр, речь)

- **Ren'Py официально рекомендует Opus первым**: quickstart 8.5.4 — «Audio files should be in
  opus, ogg vorbis, or mp3 format»; автор движка PyTom (Lemma Soft, 23.06.2020): «I'd
  recommend opus for new audio, if you can support it». Раньше (2012): «Ren'Py will support
  Ogg Opus, and that will very likely become the preferred format».
- Opus — IETF-стандарт RFC 6716 (2012), royalty-free (3-clause BSD + патентная лицензия);
  судебных дел нет. MP3-патенты истекли 16.04.2017; AAC до сих пор патентный пул — мимо.
- Студийные пользователи Opus для речи: Source Engine (voice chat), PS4/PS5-party-chat,
  Discord, WhatsApp, Zoom. Unity/Godot/FMOD/Wwise — нам не мешают (движок Ren'Py).
- RPA-архивы Ren'Py не сжимают, только упаковывают; zip/bz2 дистрибутива поверх Opus дают
  минимум (уже сжатое).
- Ключевое свойство Opus для нашего кейса: «Unlike Vorbis, Opus does not require large
  codebooks for each individual file, making it relatively more efficient and resilient for
  short clips» (Wikipedia Opus) — у нас тысячи клипов по 5–15 с.

### FLAC (lossless)

- Стандарт: RFC 9639 (декабрь 2024), patent-free; библиотеки BSD, утилиты GPL.
- 24 kHz имеет выделенный код в заголовке фрейма (RFC 9639 §9.1.2) — наша частота
  subset-native; битность 4–32, sample rate 1 Hz–1 048 575 Hz — 24 kHz/16-bit в лимитах.
- Последний релиз FLAC 1.5.0 (11.02.2025): многопоточное кодирование `flac -j #` — на
  7800X3D батч 119k файлов раскидывается по ядрам.
- Коэффициент сжатия: типично 50–70% от WAV; статистика 4461 трека (Pigeon 2012): avg 0.546;
  наш корпус (речь): **59%** (замер 2026-10-12, сэмпл 25). Compression level: -5 → 0.520,
  -8 → 0.516 (выигрыш 0.4 п.п. при 2.5× медленнее кодировании; с -j разница стирается).
- Скорость (i3-10100T, single-thread, ktf rev.6): encode -5 ~549× realtime, decode ~767× —
  нагрузка в игре нулевая, батч-конвертация быстрая.
- Экосистема: единственный lossless с рантайм-поддержкой в Ren'Py (ffmpeg-бэкенд, проверено
  по бинарнику), Windows 10/11 native flac.dll, macOS 10.13+, iOS 11+, Android, браузеры
  <audio> 97.26% (caniuse). WavPack/ALAC/APE/TAK сжимают на 2–5% лучше, но нигде не играются
  в нашем стеке и декодируются медленнее — вычёркиваются.
- Ren'Py web-сборка: `config.webaudio_required_types = ["audio/ogg", "audio/mpeg"]` (конфиг
  7.4.11), `_audio.js` грузит файл байтами и вызывает `decodeAudioData` → FLAC в вебе зависит
  от браузера. **Веб-сборка для TSSR неприменима** (Steam-десктоп; лимиты itch 1000 файлов /
  500 MB не релевантны).

### Opus (lossy, прозрачный для речи)

- RFC sweet spots для речи (20 ms frames): NB 8–12, WB 16–20, **FB 28–40 kbit/s**; Xiph
  Recommended Settings (ред. 16.09.2026): VoIP mono 10–24, audiobook mono 24, **SWB voice
  14 / FB voice 16 kbit/s**. Наш 24 kHz источник → Nyquist 12 kHz = SuperWideBand — таблица
  даёт 14 kbit/s для voice; 48 kbps не добавляет полосу ( режется до 12 kHz), только чистоту
  внутри SWB.
- IETF listening tests (draft-ietf-codec-results-03, Google/Nokia/Tübingen): Opus WB 19.85
  kbps значимо лучше всех конкурентов; «32 kbps almost transparent»; parity с AMR-WB с 24
  kbps; 64 kbps stereo MUSHRA 95.58 vs ref 97.36.
- Opus 1.5 (2024)/1.6 (15.12.2025): NoLACE «usable down to 6 kbps», «9 kbps close to
  transparency»; ML-фичи выключены по умолчанию; libopus 1.6.1 (14.01.2026) — в нашем
  ffmpeg 8.1.2.
- caniuse (март 2026): Opus <audio> 92.84% + 4.42% partial; Safari partial = только
  CAF/WebM — Ogg-Opus в Safari <audio> НЕ играет; iOS Safari 18.4+ полноценно. **Для десктоп
  Steam-игры не релевантно.**
- RFC 7845: pre-skip сохраняет длительность/синхронизацию; Ogg Opus всегда 48 kHz на выходе.
- `application=voip` vs `audio`: разница <0.1%. DTX (тишина → 1 кадр/400 мс) в ffmpeg не
  применяется (`-dtx` не работает), нужен `opusenc --set-ctl-int S:4016=1` — экономия на
  паузах реплик, опционально.

### Результат прослушивания человеком (2026-10-13, стенд tmp/audio-exp/)

- Тестовая реплика: Narrator, AlfredArc, 26fc002f, 18.16s, mono 24 kHz; конверты: FLAC,
  Opus 16/20/24/32/48k, Vorbis q5, MP3 128k (ab.html + отдельные файлы).
- **Человек: между Opus 16k / 24k / 48k разницы НЕ слышит** («не слушаю разницы между
  ними»). Это ожидаемо и совпадает с ресёрчом: источник 24 kHz → полоса 12 kHz (SWB);
  Xiph-таблица: SWB voice = 14 kbps; IETF: 32 kbps almost transparent для FB-речи; наш
  clean TTS + loudnorm — самый лёгкий для кодека сигнал.
- Вывод: 16k уже прозрачен на слух для этой реплики, 24k — с запасом (Xiph-рекомендация),
  48k избыточен.
- **Решение человека (2026-10-13): стандарт = Opus 24 kbps mono.** Обоснование: между
  16/24/48k на слух нет разницы; 24k взят как «скучный стандарт» с двойным запасом над
  Xiph-планкой SWB-voice (14 kbps) — страховка на шёпот/визг/смену рефов; стоимость запаса
  vs 16k = +0.4 GB на весь корпус. **Мульти-голосовой A/B (женские/мужские/эмоциональные)
  признан ненужным**: тот же 24-кГц-сигнал той же полосы, кодеку не сложнее; наука
  (IETF/Xiph) + слух человека на 18-секундной наррации закрывают вопрос прозрачности.
- Осталось добить перед финальным «Результатом»: замер ≥250 файлов (уточнить % сэмпла),
  тест в игре 7.4.11, оформление таблицы по 6 критериям.
