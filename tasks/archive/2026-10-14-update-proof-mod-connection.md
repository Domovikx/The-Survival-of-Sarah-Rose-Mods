## Цель

Когда игра обновляется в Steam, хочется подключать наши правки (перевод UI, шрифты/размеры
шрифтов, настройка языка, озвучка), не меняя ни один существующий файл игры — после апдейта не
переприменять ничего вручную и ничего не терять.

Результат — фактура + варианты ≥2 с оценкой + вердикт: какой механизм реально работает на нашем
рантайме (Ren'Py 7.4.11.2266, Python 2.7) либо чем ближайший фолбэк. Это ресёрч: файлы игры и
код не меняем (только тестовые прототипы, которые потом убираются).

### Механизмы подключения (по убыванию чистоты)

1. **`environment.txt` в КОРНЕ установки** (рядом с exe; сейчас отсутствует):
   `renpy/bootstrap.py:177-185` — файл exec-ится как Python и пишет значения в `os.environ`
   (только для ещё отсутствующих ключей). `renpy_base = dirname(realpath(argv[0]))`
   (`TheSurvivalofSarahRose.py:141-145`) = корень установки. НОВЫЙ файл → апдейт не трогает.
   Через него задаём `RENPY_SEARCHPATH` — без системных переменных, без правок Steam/лаунчера.
2. **`RENPY_SEARCHPATH` env** (`renpy/main.py:387-389`, пути через `::`): читается ДО rpe/архивов/
   скриптов; есть с Ren'Py 7.2.1 (github renpy/renpy commit fb1a01c, PR #1766, 03.2019; проверено
   по тегам 7.2.1.457 и 7.4.11.2266), документирован (renpy.org/doc/html/environment_variables.html).
   **Пути — только абсолютные**: `main.py:397-400` — `os.listdir(dir)` по searchpath БЕЗ isdir →
   несуществующий/кривой путь = OSError → traceback.txt → exit 1 (игра не стартует, НЕ тихий
   скип). `loader.py:402-409,867-868` резолвит пути от basedir, а `main.py:397-400` — от CWD
   (os.chdir в рантайме нет, CWD при Steam-запуске не гарантирован) → двойной резолв; абсолютный
   путь работает одинаково везде. Глобальная env с ОТНОСИТЕЛЬНЫМ путём опасна для других
   Ren'Py-игр (краш на main.py:398); с абсолютным — чужая игра получит наш мод-дир в searchpath
   (для файлов с нашими уникальными именами это безвредно, но проверить).
3. **Аддитивный .rpy с уникальным именем** в мод-дир (или прямо в game/ — по наблюдению 0.79
   новые файлы апдейт не трогает): загрузится после официальных по алфавиту
   (`script.py:269 sort`, `script.py:286-291` initcode: сначала приоритет init N, потом порядок
   имени файла).
4. **`.rpe` в мод-дир** (`main.py:396-400` → `load_rpe` `main.py:151-157`: zip с autorun.py,
   exec до всего) — может добавить dir'ы в searchpath и повесить callbacks; исполняемый Python
   до init (только stdlib + renpy.*).
5. **`.rpa` в мод-дир**: архивы индексируются по всем dir'ам searchpath (`main.py:409-424`), но
   только АДДИТИВНО: дедуп `loader.py:321-336` (файловый скан раньше архивного), `.rpy` из
   архива не грузится (`script.py:240-242`) → перекрыть официальный ассет/скрипт нельзя.
6. **`config.file_open_callback`** (`config.py:366`, `loader.py:626-645`): вызывается ПЕРЕД
   файловой системой → переопределение ЛЮБЫХ ассетов (шрифты, картинки) из init python
   мод-файла. Не влияет на выбор .rpy-скриптов.
7. **`config.label_overrides`** (`config.py:339`, `script.py:908,934`) — перенаправление label
   при lookup, без дублей и без правки файлов.
8. **Будущее**: Ren'Py 8.4 получит официальные каталоги `extensions/`/`mods/` вне game/
   (renpy/renpy#6049, «This will be in 8.4») — нам не поможет (7.4.11), но подтверждает
   валидность нашего направления.

### Семантика переопределения (доказана по коду; живой прогон = контроль)

- `define` — поздний выигрывает, ошибки нет (`ast.py:2227-2228`; дубль ловит только lint
  `lint.py:575-609`). Ловушки: EARLY_CONFIG = {save_directory, allow_duplicate_labels,
  steam_appid, version...} (`ast.py:2136-2143`) выполняется при загрузке файла, до init;
  производные `gui.*` (`gui.button_text_font = gui.interface_text_font` и др., gui.rpy:159-210)
  считаются от баз — поздний define базы не перетекает в производные (пересчёт через
  `gui.rebuild()` → `renpy.ast.redefine`, наши позже по регистрации — выигрывают).
- `default` — НЕ инструмент переопределения: первый выигрывает (`ast.py:2322-2334`), в
  developer-сборке дубль падает. В игре developer=False
  (`common/00library.rpy:287-289` + `game/script_version.txt` = (7, 4, 11)).
- `style` — мерж свойств, по каждому свойству поздний (`ast.py:2656-2682`). Окно откладки:
  стили применяются после ВСЕЙ init-петли (`config.defer_styles` включает `gui.init`,
  `common/00gui.rpy:61`; закрывается `init 1001`, `00style.rpy:447`; применение
  `translation/__init__.py:606` → `main.py:82 build_styles`). Мод-style должен быть в окне
  **(-2 … 1001]**, напр. `init 999 style ...`; >1001 — перетирается официальными отложенными.
- `screen` — дублей НЕ существует: у ast.Screen `.name` = None → уникальный тюпл
  (`ast.py:398` + `script.py:317-327`), `define_screen` пишет в dict (`display/screen.py:226-228`)
  → последний выигрывает. Официальные экраны: `screens.rpy:5 init offset = -1` → prio -501;
  мод без offset = -500 → мод выигрывает НЕЗАВИСИМО от имени файла.
- `label` — репорт дублей ВЫКЛ (`script.py:961-962`: developer=False → return) → фактически
  последний выигрывает (`namemap` перезаписывается всегда, `script.py:476`); штатный штатный
  инструмент без дублей — `config.label_overrides`.
- `define gui.*` в init 999 УСПЕВАЕТ повлиять на стили: gui-глобалы читаются отложенными
  стилями в момент apply (уже после 999) — цепочка доказательства в отчёте по исходникам.

### Вердикт

**Основной механизм: `environment.txt` в КОРНЕ установки → `RENPY_SEARCHPATH` → внешний
мод-дир с аддитивными .rpy (уникальные имена, переопределения через define/screen).**

Почему именно он (метод исключения построчно):

- Правка рантайма (reddit-хак main.py, RenModder) — вычеркнута: слетает при апдейте, RenModder
  ещё и удаляет все .rpyc (чистка кэша) — противоречит цели.
- Классика «класть .rpy в game/» (де-факто сообщества) — работает (новые файлы апдейт не
  трогает, наблюдение 0.79), но оставляет мод внутри депот-каталога: verify/будущие чистки
  Steam и «чистота» установки хуже; оставить как РЕЗЕРВ (мод-дир в game/ не требует
  environment.txt вовсе).
- Глобальная env-переменная (setx) — вычеркнута: ломает другие Ren'Py-игры на машине
  (относительный путь) либо хрупка (абсолютный при переустановке); wrapper-.cmd ломает
  штатную кнопку Steam.
- Правки существующих файлов (status quo) — вычеркнуты: именно то, от чего уходим.
- Остаётся `environment.txt` + внешний мод-дир: ноль правок существующих файлов, изоляция от
  Steam (файл вне game/ и вне депота), проверено живьём на 7.4.11 (прогон D).

Плюсы решения: после апдейта НИЧЕГО не переприменяем; мод полностью вне game/; override
семантика доказана (define/screen — поздний побеждает, ошибок нет).

Недостатки и условия, при которых вердикт перестанёт быть верным:

1. **Краш при несуществующем пути** (F): если папка мода удалена/переименована — игра не
   стартует. Mitigation: инсталлятор/скрипт всегда создаёт папку (пусть пустую); либо
   переименование папки только вместе с environment.txt.
2. **Порядок по алфавиту файла**: мод-файл должен сортироваться позже официального (`zzz_`);
   устойчивее дублировать страховку высоким init-приоритетом для критичных переопределений.
3. **Мы скрываем новые официальные значения**: апдейт с изменённым define/screen не применится
   (наш поздний всё равно победит) — обязан быть детект апдейта (config.version + хэш-манифест)
   и ревью изменений оригинала.
4. Steam официально не документирует «посторонние файлы не трогаются» — факты = наше
   наблюдение 0.79 + сообщество `[СОМНЕНИЕ: прямого офиц. текста нет; низкий риск —
противоречит практике мододелов всей индустрии]`. Детект апдейта страхует и тут.

### Остаточные риски / известные грабли

- `default` — НЕ инструмент переопределения (первый выигрывает, в dev падает).
- `style` — живого прогона не делали (исходник однозначен: мерж, окно откладки -2…1001];
  применять `init 999 style ...` и проверить визуально при реализации).
- Label-дубли: репорт выключен (developer=False), фактически последний побеждает, но придумывать
  свои label-имена (или `config.label_overrides`).
- `import renpy` в `init python` запрещён (см. урок прогона B).
- Официальные `.rpyc` не конфликтуют (уникальные имена), кэш чистить не нужно.
