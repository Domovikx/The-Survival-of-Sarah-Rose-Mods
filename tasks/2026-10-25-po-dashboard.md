# [2026-10-25] Реализация: локальный дашборд перевода — HTML-страница по http://127.0.0.1

Статус: READY
Приоритет: СРЕДНИЙ (чисто удобство владельца; не блокирует план переводов)

## Задача от пользователя

«а можно ли какой-то для меня UI интерфейс сделать в котором динамично будут данные
обновляться по процессу... чисто как идея если бы где-то было что-то типа локал сервака
с html страничкой доступной по определенному урлу куда бы выводилась статистика, то было
бы круто, НО если бы это сильно жрало ресурсы ПК, то тогда лучше не надо. это задачка на
чисто интерес можно ли или нет и ресурсопотребление. потому что браузер у меня часто
открыт и было бы удобно по какому-то урлу видеть отчёт»

«опрос данных можно и уменьшить, и раз в 60с достаточно. можно попробовать оформить,
только где ? в скриптах ?»

## Цель

Когда идут фоновые прогоны перевода, я хочу открыть в уже открытом браузере
`http://127.0.0.1:8787` и увидеть живую сводку по всем языкам (пустых/переведено/скорость/судья,
состояние прогонов, VRAM), не открывая терминал и не запуская ctl-команды.
Критерий «стало лучше»: страница отдаёт корректные числа, совпадающие с `po:translate:status`
на тот же момент, потребление — единицы МБ ОЗУ и ~0% CPU.

## Контекст (проверено 2026-10-25)

- **Ресурсопотребление оценено (вопрос владельца закрыт):** node-процесс ~30–50 МБ ОЗУ,
  ~0% CPU в idle; опрос раз в **60 с** (решение владельца) — < 0.5% CPU суммарно; вкладка
  браузера ~50–100 МБ. На фоне перевода (GPU 100%, 9 ГБ VRAM) — шум. ВЕБ-ПОИСК не требовался.
- **Данные уже есть, новый сбор не нужен:**
  - `tmp/po_translate_<lang>.jsonl` — записи ok/rejected (es уже 15 МБ! → счёт по
    смещению с кэшем, НЕ перечитывать файл целиком на каждый запрос);
  - логи прогонов (`tmp/po_translate_*_run.log`, `tmp/po_translate_ui_queue.log`) — строки
    вида `[295/763] ok=... rejected=... 2.3с/зап судья≈9.8`;
  - pid/stop-файлы стоп-механизма (как использует `po:translate:status`);
  - пустые msgstr в `patches/ai-voice-pack/po/*.po` — «остаток» (можно считать при
    запуске сервера один раз + инкрементально, либо доверить ctl-статусу);
  - `nvidia-smi --query-gpu=memory.used,utilization.gpu` — по запросу (шелл раз в 60 с).
- **Конвенция размещения:** весь po-инструмент живёт в `.opencode/skills/renpy-po/`
  (`po_translate.mts`, `po_update.mts`, `prefill.mts` + npm-скрипты `po:*` в `package.json`).
  Значит дашборд = `.opencode/skills/renpy-po/po_dashboard.mts` + npm-скрипт `po:dashboard`.
- **Не изобретать велосипед:** node-зависимостей у проекта нет (только dev-тулы) — сервер
  на `node:http`, страница — один HTML с инлайн-CSS/JS, никаких CDN/npm-пакетов.
- Прецедент «скриншоты UI» (`shots_capture.ps1`) — отдельный инструмент, дашборд с ним
  не пересекается.

## Что сделать

1. `.opencode/skills/renpy-po/po_dashboard.mts`:
   - `GET /` → HTML-страница (сводка таблицей: язык | пустых | переведено | прогон идёт |
     скорость | судья; строка VRAM; «обновлено в HH:MM:SS»);
   - `GET /api/stats` → JSON (та же сводка; страница опрашивает раз в **60 с**);
   - `--port N` (default 8787), `--once` (вывести сводку в консоль и выйти — для тестов);
   - парсинг jsonl — **инкрементальный кэш смещения** (хранить размер файла и offset;
     если файл меньше кэша — пересчёт с нуля: ротация/перезапуск).
2. npm-скрипт `po:dashboard` в `package.json`.
3. Тесты `po_dashboard.test.mts` (node --test): парсер лог-строк, агрегация jsonl со смещения
   (tmp-файлы), ответ `/api/stats` на поднятом сервере (реальный порт в tmp), отдача `/`.
4. Замер фактического потребления (RSS процесса + быстрый curl) — в журнал задачи.

## Приёмка

- [ ] `npm run po:dashboard` → `http://127.0.0.1:8787` открывается, показывает все 10 языков;
      числа «пустых/переведено» на странице СОВПАДАЮТ с `npm run po:translate:status`
      (сверка в журнале, вывод двух команд рядом).
- [ ] Опрос страницы раз в 60 с; за 5 минут наблюдений сервер ест < 50 МБ RSS и ~0% CPU
      (замерить — `tasklist`/PowerShell, записать в журнал).
- [ ] При запущенном переводе страница обновляется без остановки/перезапуска прогонов
      (только чтение; никакой записи в tmp-файлы прогонов).
- [ ] `node --test` по всем *.test.mts зелёный (334+); typecheck/oxlint/prettier чистые.
- [ ] Инкрементальный кэш jsonl доказан тестом: повторный запрос не перечитывает 15 МБ
      (проверка на файле с растущим смещением).
- [ ] Edge-case: сервер занят порт → понятная ошибка; файл лога/jsonl отсутствует/пуст →
      строка «нет данных», а не краш; процесс перевода только что стартовал → страница
      не показывает stale-данные как живые (timestamp «обновлено»).

## Вне рамок (out of scope)
