Видео: Borodat, «Удали Ollama! Этот движок запускает 94 ГБ ИИ на обычной видеокарте» —
про движок **Strata** (github.com/Niko1221/Strata, 37k звёзд, MIT): запускает
Qwen3.8-Flash-Next (125B параметров, 6B активных, MoE 512 экспертов/слой) на игровой
GPU 12–16 ГБ за счёт распределения весов GPU/RAM/CPU/SSD + MTP-драфтинг. Скорость
60–100+ tok/s там, где llama.cpp даёт 23.

## Цель

Когда LM Studio с qwen3.5-9b служит LLM-бэкендом пайплайна (po-переводы 8 языков,
разметка эмоций), я хочу Strata с OpenAI-совместимым API на localhost как АЛЬТЕРНАТИВНЫЙ
бэкенд (125B-модель против 9B — скачок качества перевода), чтобы после бенчмарка
принять решение «переключать ли очередь po:translate». Критерий «стало лучше»: Strata
поднимается на нашей конфигурации, API отвечает на /v1/chat/completions, замерены
скорость/качество на переводной задаче, решение владельца записано в журнал.

### УСКОРЕНИЕ: Strata --parallel 1 → 8 (2026-11-02, найдено ресёрчем)

**Симптом:** рост concurrency клиента (c=4→c=8) НЕ повышал скорость (10–18 стр/мин,
GPU 58–61%). **Причина** (найдена в `strata status`): сервер работал на **1 слоте** —
дефолт `--parallel` = «fit to your graphics card», а на 16 ГБ карте (модель занимает
15.4/15.9) автоподбор выбрал 1. Все клиентские запросы сериализовались:
`Pre-admit 7`, `First engine token 10.759 s` (очередь), `Slots occupied --/1`.

**Фикс:** `strata launch ... --context 16k --parallel 8` (первый запуск с
`--context 32k --parallel 8` упал: KV 1.43 ГБ × 8 = 11.4 > 7.9 свободных —
контекст урезан до 16k, судье хватает с запасом).

**Результат:** `Slots 8/8, In flight 8, Pre-admit 0`, скорость **10–12 → 22
стр/мин (~×2)**, first token 0.114 с (было 10.8). ETA прогона: 3.7 → **~1.8 дня**.
Доля ниже порога не изменилась (14.9 → 15.5%) — качество судейства не пострадало.
GPU при этом 16% — узкое место сместилось в CPU-часть (8 слотов держат меньше
экспертов в VRAM — предупреждение движка) и в длину судейских цепочек (строка =
3–7 последовательных вызовов).

**Обновлённые точки старта (иначе рестап вернёт 1 слот!):** AGENTS.md (секция
«Пульт бэкендов»), скилл `lmstudio-ctl`, ночной watchdog `tmp/resume_ru_judge.sh`.

**Остаточные рычаги** (если потребуется): батчинг судьи (N-строк на запрос —

### АВТО-ПРАВКА: po_repair_full.mts (2026-11-02, по запросу владельца)

**Запрос:** «файл ru.po вообще никак не меняется, я даже качество не могу
проверить» — справедливо: чистый прогон судьи только отчитывался. Собран
инструмент **судья + авто-правка**:

- Поток: новая строка → судья → ниже порога → ПРАВКА (промпт с правилами
  systemPrompt + замечаниями судьи) → детерминированные шлюзы checkTranslation →
  повторный судья ≥9 → **writePoAtomic в .po** (файл улучшается на ходу);
  не прошёл → JSONL {repair_failed} + human-лист, файл не трогаем.
- Крэш-безопасность: СНАЧАЛА запись файла, ПОТОМ статус в JSONL; резюме
  append-only (последняя запись по msgid побеждает).
- Shaky (≤15 символов) при провале → human без правки (судья ненадёжен).
- Порог НЕ двигается: в файл попадает только кандидат ≥9.

**Тесты (по указанию владельца «помним про тесты и е2е»):**

## БАГА РОДА СПИКЕРА (2026-11-02, найдена владельцем, починена)

**Красный флаг:** `speaker:Xanthippe` (в игре — **МУЖЧИНА**, script.rpy71550-71554:
«He stuck out **his** hand», «**The man** laughed») переведён с женским родом:
«Но я **радА**, что это не закончилось трагедией». Причина: у переводчика/судьи
не было данных о поле спикера — пол лежал только в контрактах и никем не читался.

**Фикс (цепочка, всё через контракты — DRY):**

1. `casts/gender.mts` (NEW): `speakerGenders()` — производная SPEAKERS ×
   `contract.gender` (расширять SPEAKERS отклонено — продублировало бы пол
   в двух местах; контракты = единственный дом истины);
2. `potgen.mts`: тег **`#. spk_g: M|F|?`** (сокращён с speaker-gender ради
   токенов — решение владельца) в каждой речевой строке POT
   (регенерация: **68 357 тегов**, F=56 596 / M=11 761); main → async;
3. `pot_resolve.mts`: `PotMeta.gender` + аксессор + кэш `potIndex()`
   (промпты не парсят 12-мегабайтный POT на каждую строку);
4. `po_translate.mts`: строка пола в промпт **переводчика** (родовые окончания:
   «я рад ≠ я радА») и **судьи** (теперь может ПРОВЕРЯТЬ род); заодно судья
   получает тон с фолбэком из POT — recheck-инструменты передавали emotion=null;
5. `po_repair_full.mts` (вскрыто вопросом владельца «а переводчик откуда
   возьмёт»): промпт авто-правки шёл БЕЗ тона и БЕЗ пола (читал комменты po,
   которых нет) — теперь тон+пол из POT + явное требование GENDER agreement;
6. Правка самой строки в ru.po («радА» → «рад», атомарно).

**Тег течёт в po — решение владельца (2026-11-02, вариант b):** «пол виден
глазами в любом po, инлайн со спикером — вынужденная мера для удобства
ревью» → `po_update.mergePoUpdate` копирует в .po **ТОЛЬКО `spk_g`** (всё
остальное по-прежнему вырезается — DRY 2026-10-23 для arc/scene/uid/тона
сохранён). `npm run po:update` ×10 языков: **spk_g 68 357 записей в каждом
файле**, `po:check` все целы, переводы не тронуты (de 8253 / es 69120 и т.д.
без изменений). Промпты читают пол из POT через резолвер (источник один).

**Тесты (+2):** резолвер spk_g (M/отсутствие→null), прокидывание в po

## СУДЬЯ ОСТАЁТСЯ (2026-11-02, владелец: «если с судьей быстрее — фиксируем и оставляем судью»)

Альтернатива «один переводчик без судьи, поблочный проход «переведи или улучши»»
(скилл `skill-translate-rpy`, режим дописан) — проверена пилотом на ru.po
(2 сабагента, 220 блоков) и **отклонена по скорости**:

| Проход                                        | На блок   |
| --------------------------------------------- | --------- |
| Сабагент-ревью (пилот 1: 100 бл., 16.4 мин)   | 9.8 с     |
| Сабагент-ревью (пилот 2: 120 бл., 14.7 мин)   | 7.4 с     |
| Судья+Strata, медиана 88 прогонов             | 2.7 с     |
| Судья+Strata, большие прогоны (es 38k, de 2k) | 0.9–1.0 с |

Причина разрыва: судья шла параллельно 8 слотами Strata, сабагент — один
поток + накладные (чтение файла, edit-раундтрипы, po:check, отчёт). На весь
ru.po (69 120 блоков) сабагент-проход ≈ 5.9 дней против ~19 ч у судьи.

**Итог: боевой конвейер — `po_translate.mts` со судьёй (порт не трогаем).**
Режим «переведи или улучши» в `skill-translate-rpy` остаётся как ИНСТРУМЕНТ
точечного ревью (ручные выборки, разбор находок) — не для массового прогона.

Положительная находка пилота (220 блоков, 8 правок ≈ 3.6%): сабагент ловит
файловые несогласованности, которые построчный судья не видит («Летрем» 40 vs
«Летрам» 212, глоссарий-сверка). Эти классы дефектов — зона `po-audit`/ручного
ревью, а не судьи.

Проверка гендера при этом (2026-11-02): `gender.mts` ↔ контракты ↔ теги
`#. speaker_gender:` во всех ru.po-блоках — **0 расхождений** (полная сверка);
guard-тест зелёный; «расхождение Carolyn M/F» из отчёта пилота 2 — ложная
тревога сабагента (все 783 Carolyn-блока = F, gender.mts = F, контракт = F).
