## Цель

Когда есть стабильный дистрибутив, пользователям нужна ссылка «Latest release» вместо master.zip
(который собирается заново на каждый push и может содержать недоделанное). Релиз даёт: понятный
URL, счётчик загрузок, changelog, отдельную индексацию GitHub-релизов, стабильную ссылку для постов
в соцсетях. Критерий: релиз существует, ссылка стабильна, README и Pages-лендинг на неё ссылаются.

## Что сделать (ресёрч, по протоколу `tasks/AGENT.md`)

Вопросы ресёрча при выполнении:

1. Когда выпускать релиз: сейчас (перевод 100%, озвучка 94.2%, пометить как beta) vs после 100%
   озвучки? Гипотеза: сейчас — betа-релиз, потому что трафик из внешних площадок (см. задачу
   external-promotion) не будет ждать неделю; статус в описании релиза указать честно.
2. Что в changelog: только цифры (перевод 68 254 строки, 94.2% озвучки, Opus 24 kbps, ~1.6 ГБ)
   vs подробный список арок? Гипотеза: кратко + таблица готовности арок из README.
3. Триггеры: ручной `gh release create` vs GitHub Actions на тег? Гипотеза: ручной — проект без CI,
   автоматизация не окупается.
4. Дистрибутив релиза: GitHub-релиз без ассетов (ссылка на source zip) vs загрузить zip с
   переводом+озвучкой (~1.6 ГБ, лимит GitHub-ассетов 2 ГБ на файл)? Гипотеза: source zip GitHub
   уже даёт, ассет не нужен — но проверить фактический размер и лимит.

Факт для проверки при выполнении: лимит GitHub Release Assets — 2 GiB на файл (docs.github.com,
сверить датой выполнения). [УТОЧНИТЬ]
