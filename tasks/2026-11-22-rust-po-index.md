# Rust: индекс PO/POT вместо парсинга на каждом запуске

**Статус:** READY (замеры сделаны 2026-11-22, решение владельца ожидается)
**Порог:** прирост ≥ 10 % от общей длительности команды на реальных данных
(правило владельца 2026-11-22, `AGENTS.md` → «Профит считаем в процентах»).

## Цель

Убрать из `voice_status` / `stats` повторный парсинг 141 МБ PO и MD5 каждой
строки на TS: Rust-CLI один раз строит индекс (uid, arc, category, who, emotion,
перевод по языку), TS-команды читают артефакт и остаются источником логики.

## Что уже сделано (Фаза 0, TS, 2026-11-22)

`loadCatalog` в `tools/generate/scripts/voice_batch.mts` перестал разбирать
`template.pot` на КАЖДЫЙ язык: POT парсится один раз (`potRows`), `po/<lang>.po`
кэшируется по mtime, итоговый каталог — тоже.

| команда               | было   | стало  | Δ     |
| --------------------- | ------ | ------ | ----- |
| `voice_status --fast` | 13.9 s | 7.8 s  | −44 % |
| `npm run stats:check` | 22.9 s | 12.2 s | −47 % |

Проверено: `stats:check` (golden-числа), `test:voice:corpus`, `test:speakers`,
`test:casts`, oxlint/prettier — зелено.

## Замер Rust-прототипа (тот же корпус, паритет по отпечатку)

Прототип: `tmp/rust-bench/` (в git не идёт), cargo 1.100.0, msvc.

| нагрузка                                 | TS       | Rust     | Δ                |
| ---------------------------------------- | -------- | -------- | ---------------- |
| POT + `ru.po`: parse + md5 uid           | 935 ms   | 489 ms   | −48 %            |
| POT + все 10 `po/*.po`, каталог по языку | 7 406 ms | 2 649 ms | **−64 %** (2.8×) |

Паритет: одинаковый отпечаток `filled=691200 uid=f1b73a2d980a57ea8fe5a6fa3e843a29`,
per-language счётчики совпадают; `entries=69120`, категории
`[dialogue 25121, narration 43236, menu 525, ui 238]`.

Проекция на команды (по профилю: каталог ≈ 6.3 s из 7.9 s у `voice_status`):
`voice_status` ≈ 4.2 s (−47 %), `stats` ≈ 8.5 s (−30 %). Порог 10 % пройден
с запасом даже на однонитевом прототипе без оптимизаций.

## Ресёрч-вопросы перед реализацией

- Где живёт артефакт индекса: `tmp/` (не переживает чистку) или `catalog/`
  (артефакт сборки, как `label_arc.json`)? Инвалидация — mtime+size POT/PO или
  хэш содержимого?
- Нужен ли индекс «перевод по языку» внутри, или TS продолжает читать po сам
  (тогда Rust отвечает только за POT: 1/10 работы, но и риск расхождения меньше)?
- Кто собирает `cargo build --release` в пайплайне/CI: `npm run potgen` (POT уже
  перегенерирован) или отдельный шаг перед `stats`?

## Приёмка

- Юнит: порт `po_core.test.mts` (unescape, msgctxt/msgid, многострочные
  продолжения, `uid = md5`), `cargo test`.
- Е2Е-паритет: на реальном корпусе отпечаток Rust == TS (как в замере выше), плюс
  `npm run stats:check` не меняет `config/stats.generated.ts` ни на байт;
  `voice_status --json` совпадает с текущим выводом.
- Бенч: медиана 5 прогонов, отчёт в % от базовой длительности команды.

## Вне задачи

- Переписывать на Rust `voice_batch` (GPU/ffmpeg-связан), `build_pack`
  (subprocess 7z), сайт (vite уже нативный) — выигрыша нет.
- Переносить в Rust мелкие команды (`po:check` 0.4 s, `dedup-dry` 0.36 s,
  `speakers:check` 0.4 s) — нечего окупать.
